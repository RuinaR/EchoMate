[새 테스트·화면·전체 결과](RESUMED-MEMORY-UX-QA.md).

이번 검사는 레이아웃과 실제 동작을 구분한다. [81개 정적 호출 지점](UI-CONTROL-INVENTORY.md), [이전 기능 연결 표](UI-FUNCTIONAL-AUDIT.md)를 보존한다.209개 동적 버튼·토글 디스패치는 반복 내비게이션을 포함하며81개 전부의 모든 실패 조합을 증명하는 숫자가 아니다.

## 수정한 결함

1. 기록 편집·삭제창을 연 뒤 서버/사람/기록/검색이 바뀌면 새 대상으로 요청이 향할 수 있었다. 적용 시 원래 선택 문맥을 재검증하고 재오픈을 안내한다.
2. 요약 삭제 확인을 잘못 입력해도 작업 없이 창이 닫혔다. 유효하지 않으면 입력을 유지한다.
3. 일반 입력창·이름·프로필 목록은 비동기 저장 결과 전에 닫혔다. Controller가 안전한 성공/실패 결과 Future를 돌려주고 창이 결과를 확인한다. 실패 시 입력을 보존하고 연타를 막는다. 진행 중 닫기는 원자 저장의 취소/롤백으로 위장하지 않고 완료까지 기다린다.
4. 실패 안내가 길어지면 적용/닫기 버튼과 겹칠 수 있었다. 실제 텍스트 크기로 footer·창 높이·스크롤 범위를 다시 계산한다.
5. 초기화 이전/종료된 Controller도 명시적인 실패 결과를 돌려준다. 실패 결과는 이후 새로고침으로 error가 지워져도 바뀌지 않는다.

실제 SQLite 잠금 → 실패/입력 보존 → 잠금 해제 → 재시도 성공, 편집 중 행 삭제 → 실패/자료 비부활, 기본 프로필 보호, 잘못된 JSON·쓰기 오류·취소를 검사했다. 임시 DB만 사용했다.

## 레이아웃과 실행 범위

최종 숨긴 Tk 렌더420조합 PASS, p50/p95 3.712/61.267ms·최대132.656ms, callback 오류0. 이전420과 워밍업/부하가 달라 인과적 속도 향상으로 주장하지 않는다. 최종 디스패치는209건 PASS·Controller 오류0·하위 외부 HTTP0이며 일부 모델/시작/파일 선택 경계는 mock이다. 각 결과에는 소스 해시를 남긴다.

native 창 장식·파일 선택창·실제 클릭/키보드·시각적 접근성은 [사용자용 확인](USER-MANUAL-QA.md)으로 남긴다. 자동 레이아웃/디스패치/저장 후조건을 하나의 전수 실사용 PASS로 합치지 않는다.

상태·오류 상세창은 연 시점의 snapshot이다. 실시간 상태는 메인 진행 상황 화면에서 확인한다. 캐릭터 설정 변경 중 취소된 요청의 자동 재생성은 기존 동작을 유지했으며, 모델 전환의 대기 요청 보존 검사와 혼동하지 않는다.

## 검사 경계 누락의 정정

초기 디스패치 두 실행은 가짜 토큰 인증 요청이 나가는 실수가 있어 폐기했다. [정밀 QA의 정정 기록](PRECISION-SOCIAL-QA.md)을 따른다. 이후 SDK HTTP mock·하위 aiohttp 차단·Controller 오류 실패 판정을 추가했고, 최종 실행은 이 경계를 단언했다. 실계정이나 운영 토큰을 사용하지 않았다.

프로필 ID 직접 입력을 없앴다. 내보내기는 현재 적용한 캐릭터를 JSON으로 저장하고, 가져오기는 새 ID로 보관한 뒤 프로필 목록에서 적용한다. 기존 프로필/운영 설정/DB/모델/일반 JSON 덮어쓰기를 거절한다. 파일 선택 취소·실패 안내·실제 저장 내용과 기존 파일 바이트 보존을 회귀 검사했다. native 파일 선택창의 실제 조작성은 사용자 확인으로 남긴다.
