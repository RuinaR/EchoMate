# Lime 관리 앱 사용 안내 — 출시 전

**현재 RELEASE BLOCKED이며 Discord 실사용 준비 완료 버전이 아니다.** 설치/이름/GPU 기술 검사를 통과하면 Discord 자격 증명 없이 LOCAL_CHAT을 사용할 수 있다. 현재 청자 품질 gate 실패로 Discord 자율 참여/봇 켜기는 차단되며 이를 우회해 실서버에서 시험하지 않는다.

## 실행과 자료 위치

소스 실행은 루트 `EchoMate.vbs`, Portable은 배포 폴더의 `EchoMate.vbs`다. 기본은 Lime 관리 화면이다. 모델/개인 자료는 배포 파일에 포함하지 않는다. 소스는 기존 데이터 ROOT 아래 `lime/`, 배포판은 사용자별 데이터 ROOT 아래 `lime/`에 새 자료를 저장한다. 실제 데이터 ROOT는 배포 설정에 따라 결정되며 앱 코드를 이동한다고 운영 자료를 자동 이관하지 않는다.

과거 앱이 필요한 경우 `wscript EchoMate.vbs /legacy`로 명시적으로 실행한다. 두 앱은 serving lease를 공유하므로 동시에 모델을 소유할 수 없다. 기존 Gemma·설정·기억은 그대로 보존한다. legacy 자료를 Lime의 경험으로 자동 복사하지 않는다.

## 모델 설치 → 이름 → 로딩

1. 라임 화면의 라이선스·설치 정보를 읽는다. Lime 제공 조건/llama.cpp/CUDA 조건은 별개다. 확인 후 다운로드 창에 `동의`를 입력한다. 약5.8GiB GGUF와 두 엔진 ZIP, 추출 공간 및 별도 안전 여유가 필요하다. 최신 고정 파일만 사용한다.
2. 이미 동일 파일이 있다면 **기존 파일 가져오기**에 GGUF 및 두 공식 b11721 CUDA12.4 ZIP의 전체 경로를 입력한다. 원본을 옮기지 않고 별도 복사한다. 다른 revision/양자화 파일은 호환된다고 가정하지 않는다.
3. 작업 취소는 부분 파일을 보존한다. 재시도는 서버가 정확한 byte range를 주는 경우 이어 받고, 전체 응답이면 새로 검증한다. 손상/부분 파일은 설치 완료가 아니다.
4. 이름 변경에서1~32자 자기 이름을 저장한다. CharacterId는 계속 `lime`이며 기억/친밀도/동의/알림은 이름에 종속되지 않는다. Discord 프로필/닉네임은 변경하지 않는다.
5. 모델 로딩·검증을 실행한다. 자원 검사를 통과한 한 개 모델만 로딩하며 이름 확인과 청자 검증을 각각 수행한다. 기술·이름 검사는 통과했지만 청자 검사만 실패하면 LOCAL_CHAT 모델은 유지되고 봇 켜기는 비활성이다. 자원/파일/기술 검사 실패는 로컬에서도 허용하지 않는다. 반복 클릭/기준 완화로 우회하지 않는다.

## 오류 복구

- 네트워크/공간/권한 오류: 작업을 취소하고 표시된 상태를 확인한다. 다른 앱 종료·시스템 설정 변경을 자동 수행하지 않는다. 파일 검증 또는 동일 작업 재시도로 확인한다.
- 설치 손상/중단된 추출: 모델이 완전히 해제된 상태에서 **설치 복구**에 `복구`를 입력한다. 해당 설치 폴더의 손상/부분 파일과 엔진은 `.rejected`로 보존된다. 원본 가져오기 파일/기억은 수정하지 않는다. 이후 공식 다운로드 또는 가져오기로 다시 설치한다. 이전 보존본이 있으면 덮어쓰지 않고 중단하므로 수동 백업이 필요하다.
- RecoveryRequired/모델 해제 실패: 새 모델을 겹쳐 로딩하지 않는다. 상태·오류를 확인하고 앱을 정상 종료한 뒤 재실행한다. 실패가 지속되면 진단의 단계/오류 유형을 전달하며 토큰·기억·개인 로그 원문은 공개하지 않는다.
- 이름/서명 설정 손상: 원본을 자동 초기화하지 않는다. 백업 확인이 필요하며 완전한 UI 복구 마법사는 아직 미구현이다.

## Discord 설정과 최종 검증

Discord 설정의 봇 정보 등록은 로컬 암호화 저장이다. 실제 인증/서버 조회/연결/명령 등록/송신과 구분한다. 최종 승인 전에는 실제 토큰으로 연결하지 않는다. 새 모드의 `/캐릭터`는 읽기 전용, `/동의`는 본인 동의·철회용이며 실제 원격 등록/접근은 아직 미검증이다.

청자/자유 생성 사실성·확장 Runtime·장시간·배포 실환경 gate를 먼저 통과해야 한다. 그 뒤 실제 Discord 테스트는 읽기 전용 인증·Gateway·명령 변경·송신·프로필 변경을 분리한 계획/승인 범위로 진행한다. 현재 사용자가 실서버 시험만 하면 되는 상태가 아니다. [남은 차단과 QA](LIME-WINDOWS-APP-QA.md), [릴리즈 추적표](RELEASE-CHECKLIST.md).

## 로컬 채팅

모델 로딩 후 ‘로컬 채팅’을 연다. 합성 A/B·채널1/2를 구분하며 일반 문장은 기억/예약을 자동 실행하지 않는다. Enter 전송, Shift+Enter 줄바꿈, 선택 후 Ctrl+C 복사, 생성 취소, 초기화, 명시 세션 저장/불러오기를 사용한다. 검증 전 스트리밍은 완료 응답이나 실행 영수증이 아니다.

테스트 명령: `/동의 기억 켜기`, `/동의 관계 켜기`, `/친밀도 50`, `/기억 저장 나는 바둑을 좋아한다`, `/기억 목록`, `/기억 정정 앞8자리 새내용`, `/기억 삭제`, `/알림 10분 후 물 마시라고 알려줘`, `/알림 목록`, `/알림 취소 앞8자리`. 모두 별도 합성 DB에만 적용한다. 알림은 로컬 inbox에 표시하며 실제 Discord 송신이 아니다. 목록 번호는 본인 자료만 정정/취소할 수 있다.

대화 초기화는 명시 저장한 테스트 기억까지 삭제하는 기능이 아니다. 기억 삭제는 별도 명령을 사용한다. 삭제/정정/동의 변경 후 저장 세션의 근거가 달라졌다면 이전 세션 불러오기를 거절한다. 파일을 보존하고 새 세션에서 계속한다. 문맥 예산에서 제외한 과거 대화 수를 상태에 표시하며 보이지 않는 오래된 내용을 모델이 실제로 기억한다고 가정하지 않는다.

모델의 자유 생성에는 거짓 조회 약속/사실 확대 오류가 남아 있다. 기능 상태·영수증·합성 DB를 우선하고 대화만 보고 성공을 판단하지 않는다. [현재 실제 검증](LOCAL-CHAT-QA.md).


로컬 알림은 합성 받은 편지함에 표시된다. **알림 확인**을 눌러야 해당 로컬 항목을 확인 완료로 기록한다. 중단된 처리나 확인 실패는 전달 성공으로 가정하지 않는다. 알림 서비스 실패 시 새 예약은 차단하며 목록·취소는 유지한다. 실제 Discord 전달과 별개다.

명령 취소는 DB 트랜잭션의 자동 rollback을 뜻하지 않는다. 결과 불확실 안내가 있으면 목록과 동의 상태를 확인한다. 이름 변경은 저장되지만, 사용자가 과거 이름을 사실처럼 주장하면 모델이 따르는 장기 대화 오류가 확인돼 아직 출시 차단이다.

현재 Windows 세션의 최신 앱들은 데이터 폴더가 달라도 하나의 serving 소유권을 공유한다. 다른 세션/이전 바이너리에까지 이 보장을 확대하지 않는다. 가져오기는 지정한 외부 원본 파일을 읽고 고정 크기·SHA256 검증 후 복사하며 원본은 수정하지 않는다.
