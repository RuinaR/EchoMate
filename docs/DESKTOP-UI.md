# EchoMate 로컬 관리 앱

2026-10-19. `EchoMate.cmd` 더블 클릭 → 채널 설정 → **봇 켜기**. 앱은 사용자가 닫은 상태로 유지했다. Tk Canvas로 패널·선택 목록·스크롤바·버튼·토글·선택 칩을 직접 그린 다크 UI다. 운영체제 창 테두리는 유지한다. 추가 유료 프레임워크/서비스나 원격 관리 포트를 사용하지 않는다. [단계별 실제 테스트 방법](TESTING-DISCORD-APP.md).

- **대화할 곳:** 모델을 켜기 전에도 초대된 서버 전체와 현재 접근 가능한 채널/활성 스레드를 표시한다. Ctrl+클릭으로 여러 곳을 선택해 채팅/반응 규칙을 저장한다. 선택만으로 활성화되지 않는다. 선택 전 저장 버튼은 비활성화하고, 부모 채널을 고른 경우만 하위 스레드 적용 옵션을 제공한다.
- **응답 방식:** 글로 답하기/이모지로 반응하기/Discord 기본 스티커 토글. 채널에서 반응을 허용했지만 이모지 기능이 꺼졌다면 해당 설정 화면으로 안내한다.
- **성격과 기분:** 기분·먼저 참여하는 정도·다정함·귀여움·장난기·최소 발언 간격·후속 대기 시간·모델. 시간은 초/분, 성격은 %를 표시한다. 캐릭터 변경은 이력을 유지한다. 이미 하던 대화는 신규 참여 확률과 별개다.
- **진행 상황:** 처리 중/대기 요청, 기억 중인 채널, 최근 답변에 걸린 시간, 단계·경과. 본문/토큰은 표시하지 않는다. 꺼진 경우 시작 안내를 표시한다.
- **실험 기능:** 이미지/GIF/커스텀 에셋 픽셀 분석을 하나의 토글로 제공한다. 기본 OFF이며 이전 QA의 vision=true를 자동 계승하지 않는다. ON이어도 송신은 Unicode와 Discord 기본 스티커만 허용한다.

봇 켜기는 응답을 함께 허용한다. 준비 중/실행 중에는 중복 시작을 막는다. 연결된 상태에서 응답 허용만 끄면 현재 생성을 취소하고 이미 받은 문맥은 보존한다(일시정지 중 새 메시지는 받지 않음). 응답 재개는 모델을 다시 로드하지 않는다. 봇 끄기/창 닫기는 연결/모델을 정리하고 응답 허용을 끈다. 실제 대화 이력은 종료 시 정리한다.

등록 미디어 파일/태그/승인/등록 명령/전송 기능은 제거했다. 예전 비공개 파일은 삭제하지 않았다. 기본 스티커는 Discord 공식 STANDARD 팩 메타데이터로 구분하며 설명·태그를 실제 이미지 관찰로 표시하지 않는다. 서버 GUILD 스티커와 커스텀 이모지는 전송하지 않는다. 기본 스티커 API가 실패하면 해당 기능만 보수적으로 제한한다.

키보드: 목록은 위/아래, Space/Enter로 선택한다. 버튼/토글은 주 캔버스에서 Tab/Enter로 이동·실행한다. 목록 스크롤은 휠과 직접 그린 스크롤 트랙을 사용한다. 현재는 Canvas 컨트롤이라 네이티브 UI Automation/스크린리더 완전 지원은 미확인이다. 설정 저장 오류는 상단 상태에 표시된다.

## 참고한 구조

[Obsidian Appearance/Settings](https://obsidian.md/help/settings)의 어두운 사이드바/설정 영역 분리와 [LM Studio 모델 로딩 안내](https://lmstudio.ai/docs/app/basics)의 준비 상태 구분을 참고했다. 외부 앱을 설치하거나 자산·코드를 복제하지 않았다. 색상/간격/캔버스 컨트롤은 이 프로젝트에서 구현했다.

스티커 구분은 [Discord 공식 Sticker Resource](https://docs.discord.com/developers/resources/sticker)의 STANDARD/GUILD 타입과 [discord.py API](https://discordpy.readthedocs.io/en/stable/api.html)의 StandardSticker/공식 팩 조회를 따른다. 실제 스티커 송신 성공은 SDK 타입 검증과 별도로 Discord QA가 필요하다.
