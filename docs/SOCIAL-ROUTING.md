## 실행 경로

1. 허용 서버·채널/스레드·중지·권한을 확인하고 실제 작성자/멘션/reply/호칭 후보를 분리한다. 이름 언급·인용·보고된 호출은 명확한 현재 호출과 다르다. Members Intent나 서버 전체 회원 조회를 추가하지 않는다.
2. 명확한 현재 봇 호칭/선두 봇 ID 호출/실제 봇 원본 reply는 답변 자격을 보존한다. 모호한 문장 중간 멘션은 자동 초대가 아니다. 타인 mention도 문장 주어/화제로 쓰였다면 곧바로 청자로 취급하지 않는다. 실제 reply 작성자와 언급 대상이 다를 수 있다.
3. 새 발언은 임시 요청 상태로 보관한다. 실제 reply나 확인된 상대의 새 직접 초대 외에는 최신 세션/유일한 세션에 확정 연결하지 않는다. 같은 작성자라도 독립 질문은 보존하고 명확한 기존 요청 보충만 원본에 병합한다.
4. 관련 후보를 최대4개 제시한다. 같은 사람과의 확인된 관계·단어 관련도는 **후보 검색용**이며 합류 권한이 아니다. 정렬에는 last_at이나 응답 간격을 넣지 않는다. 각 후보는 실제 최근6턴과 source/reply/작성자, 확인 참여자와 현재 상대를 제공한다. 분리된 프레임으로 주고 불필요한 전체 채널 대화를 생성 문맥에 섞지 않는다.
5. 불명확한 경우 한 번의 공통 base 가중치 제약 분류로 청자·관계·후보 index·발화행위·반응 기대를 함께 판정한다. 임의 ID나 자유 형식 내부 추론을 받지 않는다. 근거가 넘치는 후보는 안전하게 보류한다. 입력은 실토큰 상한에 맞춰 오래된 부분만 줄이며 출처/답장 쌍을 유지할 수 없으면 불확실로 실패한다.
6. 봇+현재 상대도 두 구성원의 그룹일 수 있다. 언급된 제3자는 참여자로 추가하지 않는다. 애플리케이션은 실제 타인 호격/reply, 동명이인, 기존 참여 근거, source 버전, 미해결 사람 간 호출 순서를 다시 확인한다. 처음 보는 사람의 단순 평가에 yes가 나와도 자동 등록하지 않는다. 특정 봇 포함 그룹과 불특정 채널 전체는 별개다.
확인되지 않은 human 추정만으로 기존 직접 상대를 지우지 않는다. 실행 제어용 explicit_call/bot_reply 플래그는 일반 의미 판정 본문에서 제외하며 실제 source/역할/reply 근거를 사용한다. 멘션 뒤 한국어 주격/목적격/소유격은 분류용 뷰에서만 제3자 지시 표현으로 바꾸며 원본 source를 보존한다.

7. 명시적으로 부른 새 작성자의 발언은 내용에 따라 한 번의 관계 판정으로 합류할 수 있다. 자동 병합은 실제 source 관련성도 요구하며 관련성이 부족하면 별도 요청으로 답한다. 선택적 판정의 형식/문맥 오류 때문에 명확한 호출 자체를 버리지 않는다. 단독 이름 호출은 유일한 세션에 자동 합류하지 않는다.
8. 현재 상대의 새 주제가 bot new로 판정돼도 확인된 상대 관계가 있다면 신규 자율 끼어들기 확률을 재적용하지 않는다. conversation ID는 독립적으로 만들 수 있다. 다른 사람에게 청자가 전환되면 현재 상대만 분리하며 이미 진행 중인 독립 요청은 취소하지 않는다.
9. 기존 직접 상대가 없는 공개 후보는 한 번의 더 작은 분류(bot_invitation/public_reaction/broadcast_silence/other/uncertain)로 처리한다. 기존 대화의 상세 분류에 추가 투표를 붙이지 않는다. 허용된 새 자율 기회에만 활동 수준·장소별 쿨다운·실제 활성/대기 부하를 적용한다. 채널 전체 방송은 텍스트 초대가 아니다. 소유자가 반응을 허용하고 공개 성취 등에서 react가 적절하다고 판정한 경우만 이모지 전용 기회를 별도로 검증한다. 이 반응이 작성자를 봇 대화 상대로 등록하거나 텍스트 발언권을 주지 않는다.
10. 최종 action 검증·최신 범위/권한/설정/원본 확인·중복 Ledger 예약을 거쳐 실제 원본에 reply/반응한다. 실제 전송 성공 후 봇 메시지와 마지막 답변 대상을 기록한다. 참여 분류는 Discord API 호출 권한이 없다.

## 사람 사이의 청자 전환

서버+채널별 RAM 관측은 최대64곳×32발언,1시간 TTL이다. 실제 사람 호격/ID 호출·reply로 누가 누구에게 말을 건 순서를 남긴다. 이는 최신 시각의 세션을 고르는 대신 **실제 방향이 있는 발언 관계**다. 기존 상대에게 다른 사람이 질문한 뒤 그 상대가 대답하면, 이전 봇 상대라는 이유로 개입하지 않는다. 봇을 다시 명확히 부르거나 의미상 resume 근거가 있어야 복귀할 수 있다. 이 보수적인 장치는 애매한 복귀도 보류할 수 있으며 완전한 생략 청자 해석을 보증하지 않는다.

관측은 허용 범위에서만 생기고, 메시지 수정/삭제·서버/채널 무효화·개인 삭제 때 정리한다. 추정 별명이나 의미 모델이 만든 ID로 친밀도/기억/알림 대상을 조회하지 않는다. 영속 사용자 프로필이나 학습 자료를 새로 만드는 기능이 아니다.

## 시간과 자원

청자 분류 입력에는 wall clock, last_at, 봇 답변 후 경과 시간, 활동 수준을 넣지 않는다. 시간은 RAM/캐시 만료·활성 부하 lease·원본 정리·스팸·요청 기한·쿨다운·GPU·예약에만 쓴다. 같은 유효 source/관계 조건에서 간격이 달라져도 청자 입력이 바뀌지 않는다. 명시적 종료와 실제 source 만료는 따로 처리한다. 만료된 봇 원문 없이 남은 peer ID만으로 대화를 부활시키지 않는다.

선택된 요청은 기존 작성자 FIFO→대화 FIFO→단일 GPU 공정 큐→채널 송신 검증을 유지한다. 후속마다 생긴 임시 sibling은 완료 뒤 같은 확인 대화로 정리하고 원본 reverse mapping을 보존한다. 독립 대화나 대기 중 요청은 합치지 않는다. 실제 RAM 상태는32개 상한, 후보4개·관측/진단/목록도 유한하다. 장기간 안정성 보증과는 구분한다.

## Windows 진행 상황과 개인정보

진행 상황 목록에 확인된 대화와 작업을 함께 표시한다. 대화를 선택하면 현재 상태·확인 참여자 수·현재 상대 ID·마지막 답변 대상·채널을 볼 수 있다. 작업은 명시적 초대/문맥 판정, 청자, 합류/독립/상대 전환, 원본 연결, 실제 GPU 대기와 단계 시간을 보여준다. 목록 선택·스크롤을 보존하고 고급 내용은 선택한 항목에만 표시한다.

사람 간 발언/방송/불확실/합류 근거 부족/후보 과다/청자 전환 사유를 구분한다. 일반 diagnostic.jsonl은 정해진 코드뿐이며 원문/개인 기억/키를 쓰지 않는다. 기본 telemetry 저장의 화자·상대·멘션 ID는 건수로 축약한다. 소유자 RAM UI의 현재 상대 표시는 따로 유지한다. 내보내기 진단은 비식별 집계다. 실제 사유가 없는 단계를 실행했다고 기록하지 않는다.

## 실제 검증과 판정

[이번 QA 결과](SOCIAL-ROUTING-QA.md)를 따른다. 개발20/최초 미사용20/별도 미사용24/추가 통제12를 구분하고, 각 미사용 본문은 해당 최초 실행 전 튜닝에 쓰지 않았다. 이후 수정에 참고한 자료의 최신 결과는 회귀로만 보고한다. 미사용 판정 후에는 같은 세트를 다시 일반화 성능의 독립 증거로 세지 않는다. 세 모드의 의미 판정 가중치는 같으므로 반복3회는 독립60문장이 아니다.

이 기능은 한정된 로컬 GPU/모의/SQLite/숨긴 Tk 검증이며 실서버·장시간 사회적 자연스러움·사람 평가를 인증하지 않는다. 무료 뉴스 검색/장문 요약의 기존 미완료도 그대로 남는다. 실제 Discord에는 로그인·동기화·송신하지 않는다.
