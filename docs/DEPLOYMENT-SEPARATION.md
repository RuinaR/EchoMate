# EchoMate — 실행 봇과 오프라인 모델 제작 분리
작성: 2026-10-18
상태: 최신 요구사항 기준 아키텍처 설계, 아직 구현 전

## 핵심 원칙
- **EchoMate Bot**: 서버에 표시될 이름/프로필 사진 설정, 사전에 제작된 로컬 모델(페르소나 아티팩트) 로드, 대화 참여 빈도 및 활동 허용 채널/스레드 설정, 자연스러운 자동 대화에 집중.
- **EchoMate Studio**: Discord 봇과 독립된 오프라인 PC용 데이터 파일 검증·페르소나 모델 제작·품질 평가 도구.
- **DiscordChatExporter**: 별도의 외부 백업 도구. EchoMate Bot에는 과거 기록 수집·훈련·사용자 분석/친밀도 프로파일링 기능을 넣지 않는다.
- Studio는 적절한 사용 권한이 확인된 데이터로만 훈련/RAG 인덱스를 생성한다. Discord API로 얻은 메시지의 AI 학습에 필요한 Discord 명시적 허가 여부를 확인한다. 사용 툴/오프라인 여부/운영 봇 분리는 해당 요건을 면제하지 않는다.

## Bot 경계
### 설정
- Guild별 봇 닉네임 설정(Discord 서버 닉네임 권한에 따름; 현재 서버 단위), 봇 프로필 사진은 앱/봇 계정 프로필 설정 방식에 따름. 서버 단위 아바타 변경 가능 여부는 Discord의 실제 지원 범위 검증.
- 선택한 모델 아티팩트 경로 및 버전; 활성화 전에 hash, manifest, 모델 호환성, RAM/VRAM 확인.
- 활동 허용 guild/channel/thread allowlist. 차단 우선 정책.
- 발언 빈도 preset(조용함/보통/활발함), 쿨다운, 최대 발언량, 일시정지.
- Discord 공식 Bot Token은 로컬 비밀 저장소 또는 환경변수에만 둔다.
### 실행
- 봇 메시지 자기반응 방지, 중복 메시지 처리, 생성 큐·취소·오래된 답변 버리기.
- 최근 대화의 짧은 컨텍스트만 활용. 외부 메시지를 학습 데이터/모델 파라미터/지속적 개인 관계 프로필로 저장하지 않는다.
- 모델 로드 실패시 자동 대화 중단 및 안전한 상태 알림.
- 생성 모델 외 별도 온라인 AI API 필수화 금지.
- 개인정보 최소 진단 로그, stop/pause/health 상태.
### 비목표
- 학습 파일 설정/Importer/LoRA/파인튜닝
- 서버 전체 기록 백업, 백그라운드 크롤링, 상대 사용자 관계 점수화
- 여러 페르소나 동시 발언(향후 확장 가능)

## Studio 경계
### 입력
- DiscordChatExporter 등 **외부에서 생성된** 허용 파일 JSON/CSV, 공식 개인 데이터 ZIP, 사용자가 직접 작성한 예시.
- 파일의 형식/필드/기간/메시지 수/사용자별 목록을 우선 구조 검증(preview). 출처/허가 확인 없는 데이터의 학습은 잠금.
### 오프라인 제작
- 작성자별 대상 선택 → 데이터 정제 → baseline 프롬프트/스타일 → 선택적 RAG/QLoRA → 평가.
- 결과는 재현 가능한 immutable 버전으로 캐시. 아티팩트 파일의 데이터/모델 해시, 기준 시각, 평가 점수, 모델 버전 기록.
- 새 내보내기 파일을 입력하면 누락/중복/새 메시지 수 비교 후 신규 후보 빌드. 기존 안정 버전 보존.
- 사용자 동의 철회·자료 삭제 시 관련 캐시/파생물 삭제 및 재학습 계획.
### 출력
```
persona-artifact/
  manifest.json          # 공개 가능한 메타데이터만
  style-profile.json     # private
  adapter/               # optional
  retrieval-index/       # optional, private
  evaluation.json        # 개인정보 없는 측정치
```
- Bot은 아티팩트를 **읽기만** 한다. 훈련 파이프라인과 실행 중 네트워크/파일 접근 권한 분리.
- 프로필·어댑터·RAG가 로컬 LLM 추론 경로와 호환되는지 샘플 QA 이후 출판.

## 안정성 QA
1. 미승인 파일로 Studio 학습 불가, 구조 검증만 가능.
2. Bot은 모델 읽기 외에 학습/파일 수집 코드 의존하지 않음.
3. 설정 채널/스레드 밖 발언 금지, restart 후에도 유지.
4. 참여 빈도, 타임아웃, 중지 명령, 모델 전환 시 일관성.
5. 모델 변경시 버전과 성능 측정 후 명시적 활성화/롤백.
6. 노출 가능한 정보만 로깅, 개인 메시지는 Git에 올라가지 않음.

## 결정
최초에는 Bot과 Studio가 하나의 GitHub 저장소에 있더라도 **별도 Python 패키지/프로세스/실행 명령**으로 구현한다. 추후 필요하면 독립 배포한다.
