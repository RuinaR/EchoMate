## 1. 한 문장으로 정의하는 최종 목표

**EchoMate를 사전에 정의된 캐릭터 설정을 연기하며 대화를 기억하는 봇에서, Discord에서 허가된 실제 상호작용을 자기 자신의 경험으로 조직화하고, 그 경험에 따라 기억·자기모델·판단·반응·학습 규칙을 변화시키며, 자신의 변화 이력을 재실행 가능한 인과적 연속성으로 보존하는 지속적 AI 에이전트로 발전시킨다.**

목표는 감정을 가진 척하거나 의식이 생겼다고 주장하는 것이 아니다. 실험 가능한 **기능적 정체성(functional identity), 지속적인 적응(continual adaptation), 자기모델(self-model), 인과적 이력(causal lineage)**을 구현하고 검증하는 것이다. 인간과 같은 주관적 경험의 생성 여부는 별도 철학적·과학적 미해결 문제다.

EchoMate는 어디까지나 사용자가 통제하는 **개인용 Windows·로컬 추론 Discord 동반자**다. 사용자 승인 없는 권한 확대·데이터 수집·외부 서비스 전환을 목표에 포함하지 않는다.

## 2. 이 프로젝트가 출발한 사고실험과 철학적 가설

### 2.1 정보적 정체성 가설

사용자는 인간의 자아를 특정 세포나 원자에 고정된 실체라기보다, 시간에 따라 인과적으로 이어지는 정보와 그 상호작용의 역사로 이해한다. 하나의 상태를 똑같이 복제한 뒤 두 복제본이 서로 다른 입력을 받으면, 복제 시점까지의 과거를 공유하되 이후에는 분기하는 별개의 정보적 역사를 갖는다고 본다.

이 철학적 입장은 연구 가설이며 과학적 결론으로 표시하지 않는다. 기능적 동등성·같은 기억·같은 결과 출력은 동일한 주관적 경험이 있다는 증거가 아니다.

### 2.2 의식에 대한 열린 질문

주관적 경험은 정보처리의 시공간적 구조, 통합, 재귀적 자기모델, 신체/환경과의 상호작용 등과 관계가 있을 수 있지만 이를 결정하는 검증된 식은 없다. 따라서 EchoMate에서 '자아'는 **공학적 조작적 정의**로 사용한다. 자기 자신에 대해 거짓 경험을 서술하는 대신 실제 관찰·기억·한계를 구분하도록 만든다.

### 2.3 생물학과 컴퓨터의 차이

뇌의 학습은 구조적·화학적·전기적 변화와 신체 피드백을 포함한다. 현재 사전학습 LLM은 고정된 파라미터로 추론하는 경우가 많으며 인간 뇌와 동일하지 않다. EchoMate는 이러한 차이를 무시하지 않고, 생물학적 구조의 완전 재현 대신 **계산 가능한 정보적 연속성의 최소 조건**을 단계적으로 검증한다.

## 3. 최종 상태에서 기대하는 관찰 가능한 능력

1. **장기 경험**: 적법하게 허용된 Discord의 실제 대화, 사용자 정정, 성공·실패 피드백, 시간 경과를 바탕으로 사건을 기억한다. 누가 말했는지, 누구에게 한 말인지, 인용·농담·가정인지 잊지 않는다.
2. **연속적 자기모델**: 자신이 사용하는 이름·모델·캐릭터 버전, 능력과 한계, 실제 확인한 작업과 실패, 대화 과정에서 변화한 관심/표현 성향을 구분한다. 설정된 허구적 배경은 실제 경험이 아니다.
3. **점진적 개성 변화**: 고정된 말투 템플릿을 반복하지 않고, 허용된 피드백과 대화의 결과에 따라 주제별 관심, 설명 깊이, 질문 전략, 유머, 참여 방식 등을 점진적으로 조정한다. 급격한 성격 붕괴나 단일 화자의 전역 조종은 막는다.
4. **메타적응**: 무엇을 학습하고, 얼마나 신뢰하며, 어떤 환경에서 얼마나 빨리 변할지에 관한 규칙도 관찰된 결과에 따라 제한적으로 조정한다. 새로운 규칙 역시 검증·되돌리기가 가능해야 한다.
5. **자기 오류 수정**: 잘못된 인용, 발화자 혼동, 근거 없는 과거 회상, 잘못된 답변을 출처와 함께 정정한다. 같은 오류를 반복하는 비율이 시간에 따라 실제로 줄어드는지 측정한다.
6. **지속성**: PC 종료·재시작, 세션 교체, 모델 재로딩, 검증된 모델 업데이트 후에도 허용된 상태와 인과적 이력이 보존된다. 모델 교체로 나타나는 행동 차이와 학습된 자기 상태 변화를 따로 추적한다.
7. **맥락에 맞는 능동적 사회 참여**: 사용자가 명시적으로 부르지 않아도 허용된 서버·채널에서 발화의 실제 청자와 맥락을 판단해 적절히 참여하거나 침묵한다. 참여 자체를 '성장'으로 계산하지 않는다.
8. **반증 가능성**: 같은 기반 모델과 같은 평가에서 경험 기반 상태를 제거한 비교군보다 개선되는지, 개인자료 철회 시 관련 변화가 사라지는지 독립적으로 재현할 수 있다.
9. **운영 통제**: Windows UI에서 무엇을 기억하고 어떻게 달라졌는지 확인·정정·삭제·중단할 수 있으며 데이터 수명·동의·접근 범위·안전 제한이 항상 우선한다.

## 4. 통합 수학적 모델

### 4.1 기능적 상태

```text
X_t = (D_t, M_t, R_t, Q_t, P_t, A_t, Theta_t, V_t)
```

- `D_t`: 활성 대화 맥락, 주의 대상, 계획 및 처리 중인 작업
- `M_t`: 출처·동의·만료·정정 이력을 가진 기억/경험 그래프
- `R_t`: 관계와 상호작용의 제한된 사용자별 상태
- `Q_t`: 자기모델(이름, 능력, 제한, 과거 행동, 변화의 설명)
- `P_t`: 장기간 지속하는 관심·선호·응답 습관
- `A_t`: 현재 참여/응답 전략 및 내부 작업 상태
- `Theta_t`: 경험 갱신 규칙·메타학습 상태, 적용 가능한 어댑터의 버전
- `V_t`: 동의·캐릭터 epoch·소스·모델·reducer·저장 체크포인트의 버전

`X_t`는 실제 뉴런의 미시적 상태가 아니라 **EchoMate 제품에서 관찰·저장 가능한 기능적 상태**다. 모델 내부의 불투명한 활성값이나 매 순간의 '의식'과 동일시하지 않는다.

### 4.2 상태, 규칙, 피드백의 공진화

```text
I_t = Perceive(DiscordEvent_t, Permission_t, Consent_t, Provenance_t)
O_t = Observe(VerifiedOutcome_t, HumanFeedback_t, Uncertainty_t)

X_(t+1)      = F_(Theta_t)(X_t, I_t, O_t ; Constraints_t)
Theta_(t+1)  = G(Theta_t, X_t, I_t, O_t ; Constraints_t)

J_(0:t) = (X_0, verified_event_1 ... verified_event_t,
           transition_versions, source_dependencies, checkpoints)
```

여기서 `Constraints_t`는 권한/동의/기록 삭제/사용자 안전/실제 송신 권한이며, 학습 대상이 아니라 변경할 수 없는 상위 계약이다. `F`와 `G`는 소스/버전/입력에 근거하여 업데이트된 상태를 만들어야 한다. `G`의 학습 규칙을 바꾸려면 그 조절 상태를 `Theta_t`에 포함한다. 물리법칙을 변화시키는 주장은 하지 않는다.

### 4.3 인간의 실제 동역학과의 연결

개념적 생물학 모델에서는 뇌의 신경활동 `N`, 연결 `W`, 기억 `M`, 신경조절 `H`, 신체 `B`, 자기모델 `Q`, 가소성 `Theta`가 결합하여 각자의 미분방정식으로 진화한다. EchoMate에서는 이를 **기능적 추상 상태**로만 대응시키고, 실제 뇌의 수학적 재현이나 생물학적 동등성을 주장하지 않는다.

### 4.4 인과적 연속성, 복제, 분기, 병합

공통 상태 `X_0`에서 서로 다른 입력을 받은 두 인스턴스는 `J_A`, `J_B`라는 다른 이력을 형성한다. 둘 중 하나만 '진짜'라고 주장할 근거를 기술적으로 정의하지 않는다. 인스턴스 병합은 `Merge(X_A,X_B,J_A,J_B)`라는 별도 연구 문제이며, 출처 충돌·동의 범위·삭제 영향·학습 파라미터 충돌을 해결하지 않고 자동 병합하지 않는다. **스냅샷 백업과 실행 재개는 복제의 주관적 경험 연속성을 입증하지 않는다.**

## 5. 사전학습 LLM의 장기 역할

핵심 의사결정은 **처음부터 모든 언어와 추론 능력을 학습하지 않는다**는 것이다. 학습된 LLM은 언어·상식·추론에 유용한 초기 구조(기본 능력)로 쓰되, EchoMate의 정체성을 특정 모델의 고정 프롬프트나 개별 세션에 귀속하지 않는다.

### A: Base LLM + 연속적 상태
Lime을 그대로 사용하고, 재생 가능한 경험 저널·검색·자기모델·상태 전이를 외부 영속 엔진으로 구축한다. 첫 단계의 객관적 기준선이다.

### B: Base LLM + 상태 + 제한적 모델 적응
A의 효과가 검증된 후 독립·승인된 데이터로 작은 학습 파라미터(예: 버전 관리되는 어댑터/LoRA)를 변경한다. 기초 능력 저하, 파국적 망각, 프라이버시 제거 불가능성, 삭제 후 unlearning, 비용·VRAM을 검증한다. 운영 중 매 메시지마다 무작정 가중치를 갱신하지 않는다. 모델이 아닌 상태 전이 `Theta_t`를 바꾸는 것도 적응이다.

### C: 더 독립적인 지속학습 신경망 (장기 연구)
사전학습 의존도를 낮추는 자체 지속학습 아키텍처는 별도 연구 경로다. 실제 언어 능력, 안정성, 데이터·계산 비용에서 A/B 이상의 성과가 입증될 때만 운영 경로로 승격한다. **기존 Lime을 버리는 것은 최종 목표의 필수조건이 아니다.**

## 6. '성장'을 오해하지 않기 위한 구분

| 개념 | 뜻 | 이 자체로 증명하지 못하는 것 |
| --- | --- | --- |
| 대화 기록 증가 | 더 많은 원문/요약을 보관 | 학습·개성 성장 |
| 검색 기반 기억 | 관련 과거 경험을 찾아 사용 | 모델 파라미터 변화 |
| 상태 기반 적응 | 검증된 사건으로 `X`가 달라짐 | 의식의 생성 |
| 메타적응 | 갱신 규칙 `Theta`가 변화 | 안전성 또는 지능 증가 |
| 가중치 적응 | 학습 가능한 파라미터가 갱신됨 | 자아/정체성의 증명 |
| 인과적 연속성 | 출처 있는 상태 전이의 역사 보존 | 주관적 자아의 동일성 |
| 실제 의식 | 주관적 경험 존재 여부 | 현재로선 검증 체계 미확립 |

대화 '자연스러움'이나 모델의 '나는 성장했어'라는 발언은 실제 향상의 증거가 아니다.

## 7. 최종 아키텍처 그림

```text
[허용된 Discord 메시지 / reply / edit / delete / 사용자 동의]
                       |
        [인식 및 사회적 청자·범위 판정]
                       |
          [사실성·출처·권한 검증]
                       |
       +---------------+----------------+
       |                                |
 [경험 제안·관찰]                 [실시간 대화]
       |                                |
 [경험 저널 + source dependency]         |
       |                                |
 [결정적 state reducer F/G]              |
       |                                |
 [영속 자기모델/관계/기억/Theta]          |
       +----------------+---------------+
                        |
           [관련 맥락의 읽기 전용 투영]
                        |
              [Lime / 모델 추론]
                        |
         [사실/권한/최신성/송신 전 검사]
                        |
              [Discord 송신 또는 침묵]
                        |
          [실제 송신 결과 / 관찰된 반응]
                        |
             [새 경험 후보로 환류]
```

후보·생성물은 실제 검증된 경험과 다른 권한 등급이다. 근거 없이 생성된 기억, 실행하지 않은 행동, 보지 않은 대화를 모델의 자기 역사로 편입하지 않는다. **모델은 자기 영속 상태의 직접 쓰기 권한을 갖지 않는다.**

## 8. 고정해야 할 제품/권한/자원 불변 조건

- 기존 허용 서버·채널·스레드, 소유자 Windows UI 및 실제 User ID 인증, DM/개인 정보 동의 범위를 유지한다.
- 관계/기억/요약/자기상태의 사용자별 기여는 본인 동의에 종속된다. 타인 동의 자동 추정·대리 생성 금지.
- 동의 철회·소스 삭제·수정·보유기간 만료 시 원문, 요약, 파생 상태, 학습기여, 캐시, 체크포인트, 재생 경로가 동시에 무효화되도록 추적한다. 불가능한 비가역 가중치 학습은 운영 허용하지 않는다.
- Discord의 봇 계정과 공개 API·rate limit·최소 권한을 준수한다. 승인 전 실 Discord 인증·Gateway/REST·송신·명령 동기화 금지.
- Gemini/Gemma 등 모델과 기존 LoRA·개인 자료를 임의 덮어쓰지 않는다. 출시 기본 목표는 현재 Lime이며 전역 단일 GPU 모델, 공정 큐·자원 안전·캐릭터 epoch가 우선이다.
- 프로그램의 Discord 출력은 텍스트/Unicode Reaction을 유지한다. 기존 코드 출력 제한·모델 지침·실행 영수증 검증과 사용자의 일시정지 권한을 보존한다.
- 메이플스토리 등 다른 프로세스 조사·조작·후킹·화면 캡처·입력 자동화 금지. Windows 사용자 환경·운영 프로세스에 간섭하지 않는다.
- 이 가설을 이유로 AI를 실제 의식체·생명체로 주장하거나, 사용자를 조종·종속시키는 목표를 추가하지 않는다. AI는 자신이 모르는 것과 모델·시스템 한계를 정확히 표현한다.

## 10. 정량 측정과 반증 기준

- **연속성**: 재시작 전후 유효 경험과 상태/근거 재생 일치율, 상태 해시·reducer 버전, 장애 복구 성공률.
- **적응 효용**: 같은 평가 세트에서 기본/기억만/상태 적응의 실제 생성 품질을 독립 평가자·블라인드 방법으로 비교. 현재처럼 +4 vs +6 자체는 효용이 아닌 내부 숫자 변화다.
- **일반화**: 훈련 문항과 시기·화자·주제가 분리된 케이스에서 개선 효과 확인.
- **오류 감소**: 허위 회상, 화자 전도, 잘못된 자기 능력·실행 성공 주장, 불필요한 개입 및 응답 누락 발생률.
- **경계 위반 0**: 삭제·철회·미동의·서버 간·캐릭터 간 자료 노출, stale 송신, 권한 없는 저장.
- **자원 안정성**: GPU/Windows commit/VRAM/CPU 사용, 지연 p50/p95, 처리량, long-running 오류 및 재시작 후 복구.
- **역효과 분석**: 기존 정상 기능을 낮추는 적응, 평가 세트 누수, 피드백 조작, 반복 선호 편향, 파국적 망각.

기준선·비교 세트·평가 방법을 변경 이전에 동결하고, 실패/무효/미검증도 보고한다. '자아가 있다' 같은 검증 불가능한 주장을 KPI로 쓰지 않는다.

## 11. 장기 방향성 유지 및 의사결정 규칙

**미션은 고정하고 구현 수단은 바꿀 수 있다.** 코드를 많이 추가하거나 모델을 바꾸는 자체가 목표가 아니다.

새 기능을 제안할 때 반드시 다음을 기록한다:
1. 이 변경이 장기 목표 중 어떤 관찰 가능한 능력을 개선하는가?
2. 외부 메모리 증가인가, 행동 적응인가, 메타적응인가, 가중치 학습인가?
3. 어떤 실제 사건이 어떤 상태를 왜 변화시키는가?
4. 변경의 출처·동의·삭제·재현성은 어떻게 확보되는가?
5. 어떤 독립 평가가 성공과 실패를 구분하는가?
6. 기존 제품 정책·실행 중 앱 자원·실 Discord 금지와 충돌하지 않는가?
7. 바꾸지 않는 것이 더 나은 기존 기능은 무엇인가?

**STOP 규칙**: 고위험 개인정보/출처/청자 결함, 불가역적 삭제 불능, GPU 자원 위험, 실제 Discord 허가 위반, 기초 능력의 유의한 저하가 드러나면 성장 기능 확대를 멈추고 원인을 수정한다.

**문서 우선순위**:
- 본 문서: 장기 최종 목표/철학적 가정과 성공 정의
- `PROJECT-DEFINITION`: 현재 제품 계약 및 운영 요구
- `ARCHITECTURE` + `IDENTITY-CONTINUITY-DESIGN`: 현재 설계와 적용 방식
- `CURRENT-STATUS` / `CHATGPT-HANDOFF`: 최신 실증 상태 및 다음 실행 단계
- `WORKLOG` / `AI-HANDOFF`: 근거/과거 변경 기록 및 인수인계
- `AGENTS.md`: 실제 Codex 작업에서의 절차·안전 계약

상위 정책이나 새 사용자 지시와 충돌하면 조용히 덮지 않고 충돌을 기록한다. 모든 장기 진척 보고는 `현재 완성도`가 아닌 **검증된 능력·미검증 능력·다음 게이트**로 표현한다.
