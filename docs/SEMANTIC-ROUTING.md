## 원인과 확인 한계

기존 이름 인식은 올바른 호칭도 후보로만 만들었다. 이후 모델의 적절성/대상 판단이 false이면 명확한 호출이 사라질 수 있었다. 기존 후속 빠른 경로는 물음표·일부 요청 표현을 요구했고, 신규 화자 합류도 제한된 연결 표현에 의존했다. 이 조건들은 한국어 채팅의 질문·평가·핀잔 전체를 다루는 의미 판단이 아니다.

기존 비공개 진단의 수신/이름/단계 연결 정보가 부족해 사용자 보고 당시 특정 메시지가 Gateway와 Runtime에 전달됐는지는 확정할 수 없다. 첨부 화면과 사용자 설명을 근거로 재구성한 로컬 사례이며, 복구된 Discord 원본 기록이라고 부르지 않는다.

## 공통 경로

1. Gateway와 Runtime 수신, 허용 범위와 권한을 구분해 기록한다. 봇/webhook 반복 처리 방지는 유지한다.
2. 설정 이름·실제 봇 계정/서버 표시 이름·승인 별명의 제한된 호칭 형태를 검증한다. 명확한 호격/단독 이름/요청 호칭은 확정 초대이며 참여 모델의 오판으로 취소하지 않는다. 코드·URL·인용, 제3자 문장과 알려진 구성원 이름 충돌은 초대를 부여하지 않는다. 불확실한 부분 일치는 의미 판정을 거친다. 임의 철자 유사도는 사용하지 않는다.
3. 명시 멘션/확정 이름/실제 봇 reply는 일반 신규 자율 확률·쿨타임을 적용하지 않는다. 허용 범위·안전 정지·원문 완전 중복·권한·자원 한도·전송 간격은 유지한다.
4. 나머지는 공통 로컬 기본 모델의 한 번의 구조화 판단을 사용한다. 발화행위(question/request/humor/reaction/information/correction/closing/other), 대상(bot/other/group/uncertain), 연결(new/continue/end), 반응 가치(yes/no)를 분리한다. 문장부호·띄어쓰기는 필수 조건이 아니다. 질문과 발언의 수신자, 봇을 화제로 삼는 것과 봇에게 말하는 것을 구분한다.
5. 대화는 분류기 자신의 대화가 아닌 JSON 자료로 전달한다. 실제 화자·원본 답장 관계에서 계산한 마지막 봇 응답의 상대를 별도 근거로 제공한다. 문법은 출력 형식만 제한하고 의미를 대신 결정하지 않는다.
대상 오판이 관찰된 애매한 이름 언급 또는 진행 대화의 거절된 후속에만 짧은 수신자 재확인을 한다. 단독/명확한 호출과 이미 승인된 일반 후속에는 추가 호출하지 않는다. 거절된 판정을 고정 문구 목록으로 덮어쓰지 않으며 재확인도 불명확하면 침묵한다.

6. 새 화자의 주제 없는 확정 호칭은 유일한 진행 대화에 합류할 수 있다. 실제 Discord reply를 꾸며 넣지 않고 원본 호출에 답한다. 새 화자의 다른 발언은 유일한 진행 대화를 의미 비교 후보로 받을 수 있다. 후보 선정만으로 참가자/문맥을 합치지 않는다. 의미 판정에서 연결을 승인한 뒤 실제 발언만 병합한다. 독립 질문은 별도 대화로 보존한다. 후보가 여러 대화여서 애매하면 임의로 선택하지 않는다.
7. 같은 작성자의 생성 중 새 질문도 앞선 실제 답변을 기다린 뒤 의미를 판단한다. 독립 질문과 원본 reply를 보존하고 보충만 병합한다. 작성자→대화 FIFO→GPU 큐→채널 송신 잠금 순서와 단일 워커를 유지한다.
8. 참여 승인과 출력 행동·안전 검증은 별개다. 명확히 다른 사용자에게 한 멘션은 봇 대상 의미 오판을 그대로 통과시키지 않는다. 의미적 종료 외에 단순히 타인에게 한 말만으로 대화를 삭제하지 않는다.

기본/개인/성인 정책 모두 이 런타임을 사용한다. 참여 분류는 개인 LoRA 말투와 분리한 기본 모델이다. 기분·친밀도·성별은 참여 권한을 바꾸지 않는다. 기존 classify/continuity 주입 인터페이스는 호환을 유지하며, 운영 LocalBackend는 새 구조화 경로를 쓴다. routing.py의 예전 구문 기반 보조 함수는 운영 빠른 경로에서 제외했다.

## 기분 표현

기분 값은 이미 생성 프롬프트에 전달되고 있었지만 간단한 한 줄 지시였다. 이제 프롬프트 앞에서 현재 기분과 첫 반응·어휘·문장 리듬·끝맺음의 차이를 구체화한다. 성격/성별과 독립이며 자동 기분은 기존 기본 OFF다. 고정 멘트나 의식·고통·개인적 욕구를 주장하지 않는다. 힘든 상황의 공감과 기술 설명의 정보량은 우선한다.

출력 채널 보호는 유지한다. 알려진 채널 혼입이나 자모 표현 검사 실패는 최대 한 번만 새로 생성하고, 두 번째에도 검사에 실패하면 보내지 않는다. 무한 재생성하지 않는다. 추가 지연·실패는 원문 없는 지표로 기록한다. 출력의 단순 차이는 자연스러움이나 기분 전달의 사람 평가를 대신하지 않는다.

## 진단 해석

gateway_message_received/event_received는 수신 경계다. name_direct_accepted는 초대 근거, name_ambiguous는 의미 판정 필요, name_not_recognized는 단지 등록 호칭 형태가 없다는 뜻이며 후속 발언 실패를 의미하지 않는다.

followup_not_linked, continuation_rejected, autonomy_cooldown, scope_denied, permission_denied, queue_rejected, request_expired, stale_context, generation_failed, action_silence, send_failed를 실제 차단 단계에서 구분한다. autonomy_cooldown은 범위 쿨타임/신규 참여 부하 보류를 포함한다. semantic_* 코드는 분류 결과이며 정답 인증이 아니다. response_sent는 모의 transport에서는 모의 전송 완료다.

숫자 trace에 단계별 코드와 판정을 연결하지만 원문·프롬프트·토큰·사용자 ID는 넣지 않는다. 앱 진행 상황에서 최근 판단을 쉬운 문구로 확인한다. 전송 오류는 성공으로 보고하거나 자동 재전송하지 않는다.

현재 봇 행동에 대한 그룹의 3인칭 평가와 다른 사람에게 봇 정보를 묻는 것을 구별한다. target=group인 승인된 진행 대화 반응도 기존 지속 경로를 쓰며 신규 자율 참여 확률을 다시 적용하지 않는다. 평가·핀잔을 특정 고정 반응으로 바꾸지 않고 원문과 실제 대화로 생성한다. 명확한 이름은 모델이 거절할 수 없지만, 이미 기다리는 같은 사용자의 호출은 이전 답변과의 연결 여부만 판단할 수 있다. 이때도 호출 자체는 보존한다.

후보의 문맥이 판정 도중 달라지면 오래된 합류를 취소한다. 작성자 FIFO를 얻은 다음 최신 대화의 잠금을 선택한다. 거절된 옆 대화는 문맥을 삭제하지 않고 활성 집계에서 내리며, 이후 근거 있는 후속은 신규 자율 쿨타임 때문에 사라지지 않게 한다. 후보 합류의 자동 기억은 최종 흐름 ID가 정해진 뒤 큐에 넣는다. 동명이인 검사는 실제 호출한 이름 형태에만 적용한다.

QA 도구의 sequence 원문 파일은 모드별로 분리한다. 초기 도구가 마지막 모드 원문으로 덮어쓰던 것은 수정했고, 기존 단계의 결과 플래그·집계는 보존했다. 별도 재확인 실행에서 모든 모드의 전체 원문과 trace를 각각 보관한다. weights/원래 설정/운영 기억 DB를 덮어쓰지 않았다.
