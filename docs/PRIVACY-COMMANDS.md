# Discord 개인정보 동의와 Windows 관리

## 2026-10-20 명령 정리·저장소 복귀 — 최신 계약

아래의 과거 ‘pending 저장 후 다음 연결에서 자동 정리’ 설명을 대체한다. 시작 시에는 어떤 pending 승인도 실행하지 않는다. 연결을 별도 승인한 뒤 소유자가 앱에서 현재 Application ID·전역/서버별 명령 이름/종류·변경안을 확인하고 명시 승인해야 한다. 적용 전 목록 fingerprint가 같아야 하며 현재 앱만 교체한다. 적용 후 API 재조회로 `/동의`만 남았는지 검증해야 성공이고 실패/부분 완료는 pending 및 감사 기록을 유지해 다시 검토한다. 이번에는 실제 Discord 조회/변경을 전혀 하지 않았다.

현재 로컬 등록은 `/동의` 하나다. 구형 명령 미등록 오류를 저장소 실패로 표시하지 않는다. Controller/Client는 동일 CompanionStore를 공유하고, 초기 잠금 오류의 복귀는 완전한 schema7 읽기 전용 검사만 수행한다. 운영 DB 구조는 읽기 전용 확인 및 비공개 복사본 검증을 했으며 운영 쓰기 마이그레이션은 하지 않았다. [원인·실제 검증·한계](LIVE-SERVER-FIXES-QA.md).

## 2026-10-19 모델·캐릭터 분리 및 일반 배포 — 최신 기준

시작 HEAD/원격5249fd2·clean을 확인했다. 공식 기본 Gemma4 12B 하나와 독립 캐릭터를 사용하며 기존 persona/adult 고정 UI·기본 LoRA 의존을 제거한다. 이전 서명 설정은 검증 후 base로 읽고 기존 가중치/자료는 삭제하지 않는다. 성인 유머는 별도 기본OFF 정책이다. 로컬 모델/HF 캐시 탐색·호환성 검사·전환/복구, 프로필 서명 저장·편집·미리보기, GUI 첫 설정/Windows DPAPI와 Portable 런타임을 구현했다. 기존 개인정보 동의/기억/관계/요약/알림/검색/공정 큐/Unicode 반응/원본 reply를 유지한다.

청자 무공백 호격·2인칭/맞장구를 분리한 GPU 개발 재검45/46, 오개입1·누락0이었다. 추가 제외 근거를 검증기에 넣었지만 공식 no-LoRA 로더의 독립20문항은 Windows commit 부족1455로 실행을 마치지 못했다. 실제 캐릭터 생성/전체 지연 A/B·깨끗한 Windows VM·실제 Discord는 미검증이며 전체 릴리즈는 **BLOCKED**다. 이전 세 모델 QA와 숫자를 최신 구조의 성공으로 재사용하지 않는다. 사용자 데스크톱/실제 Discord 접속을 수행하지 않았다.

## `/동의` 하나만 제공

서버 구성원이 자신의 계정으로 실행하면 **본인에게만 보이는(ephemeral)** 화면을 연다. 친밀도·호칭 근거, 장기 기억, 대화 요약의 세 버튼은 독립적이다. 새 사용자는 모두 OFF다. 클릭마다 서버 ID와 실행자 User ID를 검사하며 소유자도 다른 사람의 선택을 대신할 수 없다. 5분 뒤 화면이 만료되면 다시 연다. 역할·닉네임은 인증 수단이 아니다.

화면에서 다음을 설명한다.

| 항목 | 보관하는 자료 | 보관 기간·범위 |
| --- | --- | --- |
| 친밀도·호칭 근거 | User ID와 연결된 교류 횟수·관계 상태, 반응 변화, 별명 후보와 출처 ID | 서버별 관계 상태는 삭제 전까지. 관계 변화 이력은 30일, 별명 근거는 90일. 소유자가 확정한 별명은 삭제 전까지 유지 |
| 장기 기억 | 민감정보를 제외한 본인 취향·목표·일정 등 선택 정보, 출처·시각·채널 | 상태 기본 6시간, 일정은 종료 시각+유예 뒤 만료. 목표는 최신 확인 90일 뒤 자동 활용 보류. 보류된 목표·직접 기억·취향은 삭제 전까지 남을 수 있음 |
| 대화 요약 | 동의한 모든 참여자의 실제 다중 턴 대화에서 압축한 주제·정정·결정 등, 출처·참여자·시각·채널. 과거160자 발췌는 별도 보존 | 30일 후 만료. 전체 대화 원문은 저장하지 않음. 다자 요약은 모든 사람 참여자의 요약 동의 필요 |

세 항목은 **봇 소유자의 Windows PC `local_data/bot/companion.sqlite3`**에 저장된다. PC 소유자는 파일에 접근할 수 있다. User ID와 연결되므로 완전 익명 데이터라고 부르지 않는다. 외부 모델 학습에 전송하지 않는다. 항목별 동의 외에 앱의 자동 기능과 허용 범위도 충족해야 자동 저장한다. 원문 corpus·학습 어댑터와 이 DB는 별개의 기존 비공개 자료다.

**끄기**는 새 자동 저장과 자동 활용을 중지하며 기존 자료를 지우지 않는다. 본인의 명시적 자료 확인은 가능하다. **삭제**는 선택 목록→삭제 버튼→항목 이름을 확인한 재클릭으로 수행하며 해당 동의도 OFF로 바꾼다. 다른 항목과 예약 알림은 지우지 않는다. 관계 삭제에는 별명 근거·교류 이력이 포함된다. 캐시와 관련 대기 작업을 무효화하며 대화 RAM도 보수적으로 정리한다. 선택 변경·연타 중 오래된 삭제 확인은 실행하지 않는다.

운영 DB는 WAL/secure_delete를 사용하며 관리되지 않는 자동 백업을 만들거나 삭제 자료를 자동 복원하지 않는다. 삭제는 물리 디스크의 포렌식 삭제를 보증하지 않는다. 사용자가 따로 복사한 파일·과거 외부 백업·이미 Discord에 전송된 메시지까지 지우는 기능은 아니다. 스키마·출처 삭제 표식은 대기 작업의 자료 부활을 막기 위해 유지한다.

## 마이그레이션

최신 스키마5→6은 다중 턴 요약/참여자/출처/삭제 표식을 추가한다. [다중 턴 요약 정책](DIALOGUE-SUMMARIES.md)을 함께 읽는다. 이전 스키마 4→5는 기존 관계·기억·알림·별명 레코드를 보존한다. 실제 `subject_consents`에 존재하던 본인 동의만 관계/기억으로 옮기며 opt-out을 우선한다. 과거 소유자의 암묵적 예외는 신규 동의로 만들지 않는다. 새 요약 동의는 항상 OFF다. 선택 변경에는 버전·시각을 기록하며 수집 시각과 실제 DB 쓰기 시점에 다시 검사한다. 앱의 수동 친밀도·별명 확정·기억 추가도 대상의 동의를 요구한다.

이번 QA는 임시 DB에서만 마이그레이션했다. 실제 운영 DB를 개발 검증 목적으로 열어 쓰거나 초기화하지 않았다. 다음 정상 앱 실행 시 로컬 스키마를 갱신한다.

## 관리자 설정은 Windows 앱

서버/채널/스레드·이름·모델·기분·성격·활동·관찰 건수·인터넷 조회·기억 자동 저장·관계/별명/알림 관리와 실험 캐시 관리는 앱에 둔다. 개인정보 동의를 강제로 켜는 관리 기능은 없다. 로컬 서명 키/소유자 bootstrap과 Windows 파일 권한이 관리 경계다. 같은 Windows 계정에서 파일을 읽는 사람으로부터 비밀을 숨기는 별도 보안 영역은 아니다.

앱 ‘응답 방식’의 **Discord 명령 정리 승인**에서 `동의로 교체`를 입력하면 서명된 `command_sync_pending`만 저장한다. 그다음 허용된 연결에서 이 애플리케이션의 글로벌 명령을 `/동의` 하나로 동기화하고 등록된 관리/설정 서버의 서버별 명령을 비운다. 서버 목록 밖에 과거 등록한 명령까지 발견·제거했다고 보장하지 않는다. 성공 전에는 승인을 소모하지 않으므로 실패를 진단하고 다음 허용 연결에서 재시도한다. 실제 등록 목록은 연결 전에는 알 수 없으며 코드 목록과 구분한다. 진단 감사 파일은 로컬에만 쓴다.

Discord 공식 명령어 규칙은 1~32자의 Unicode 문자 이름을 허용한다. SDK 명령 생성/직렬화와 mock bulk sync로 `/동의`를 확인했지만 실제 등록 성공을 주장하지 않는다. 글로벌 및 서버별 명령은 별도이므로 둘 다 정리해야 한다. [공식 명령어·등록/덮어쓰기 문서](https://docs.discord.com/developers/interactions/application-commands).

현재 사용자는 실제 로그인·동기화를 허용하지 않았다. 개발자가 이 문서를 실행 허가로 해석해서는 안 된다.
