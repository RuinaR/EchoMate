# 분할 메시지와 논리적 발언

## 2026-10-20 실서버 보충 — 최신 대기/초대 계약

이 절이 아래 과거0.3초 설명보다 우선한다. 근거 있는 완결형 반응의 settling은0.8초, 단독 이름/멘션 호출은2초, 미완성0.8초이며 첫 조각부터 최대4초다. 완성된 직접 질문에는 일괄 지연하지 않는다. 서로 다른 화자/범위는 섞지 않는다. 실제 호출의 미소비 초대(원본·작성자·동일 범위·수명180초)는 한 후속의 연결 후보를 보존하지만 청자/응답/종료 의미 판단을 생략하지 않는다. 이미 보낸 답변에는 소급 병합하지 않고 새 원본에 답한다.

조립/진행 요청 보충 모두 앞 조각의 첨부와 첨부 존재 상태를 보존한다. 구조화된 waiting/finalized/cancelled 기록은100개 RAM 상한, 내보낼 때 가명화한다. 기존 수정/삭제/동의/기한/원본 검증과 단일 Worker를 유지한다. [실서버 재현·GPU·한계](LIVE-SERVER-FIXES-QA.md).

## 2026-10-20 완성형 메시지의 대화 차례 후보

문장 완결과 차례 확정을 분리했다. `Pending.context`는 실제 reply, 확인된 사람 청자, 유일한 확인된 봇 직접 상대, 진행 요청의 명확한 보충, 또는 호칭만 있는 초대의 **조립 후보 근거**다. 청자 확정·초대·conversation ID 선택 권한이 아니다. 현재 직접 상대 후보는 다른 사람과 진행 중인 교류 근거가 있으면 사용하지 않는다. 같은 작성자/최근 메시지/유일한 채널 대화라는 사실만으로 후보를 열지 않는다.

- 완성형 후보는 마지막 입력부터 0.3초, 미완성 힌트는 0.8초 대기한다. 첫 조각부터 최대4초·전체64버퍼·버퍼당8,000자 상당을 유지한다. 중간 화자 도착은 타이머/내용/청자를 바꾸지 않는다.
- 확인된 문맥의 완성형 반응은 마침표·물음표·느낌표로 즉시 확정하지 않는다. 미완성 힌트의 끝 기호도 의미 종료 증거로 사용하지 않는다. 문장 중간 기호는 자르지 않는다.
- 완성형 직접 요청과 근거 없는 일반 발언에는 일괄 지연을 추가하지 않는다. 독립 요청 표시·새 명확한 호출·실제 청자/reply 전환·종료/취소·예산/기한은 경계다. 기존 호출만으로 열린 차례에는 완성형 보충도 짧게 기다린다.
- 결합한 원본의 실제 멘션 ID를 합집합으로 보존한다. 최초 사람이 청자인 발언을 뒷조각에 멘션이 없다는 이유로 봇 초대로 바꾸지 않는다. 결합 뒤에도 기존 사회적 청자·응답 계획·연결·최종 전송 검증을 모두 통과해야 한다.
- 생성 중 명확한 보충은 완성형 여러 조각도 먼저 모은다. 예산 안에서 합칠 보충만 앞선 결과를 일시적으로 무효화한다. 예산을 넘겨 별도 세그먼트로 보존할 입력이 앞선 독립 작업까지 버리던 경로를 수정했다.
- SDK는 한 전송 검증 안에서 확인한 실제 원본을 재사용한다. 최초/마지막/중간 원본과 Reaction 대상이 겹쳐도 중복 조회하지 않는다. 원본 N개는 기본 N회 GET이며 별도 Reaction 대상이나 권한 조회는 추가될 수 있다. 이전 전송/다른 작업의 오래된 객체를 재사용하지 않고 기존 SDK의 rate-limit 처리를 우회하지 않는다.

이는 의미적 동등성을 증명하는 새 분류기가 아니다. 후보 안의 모든 조각이 하나의 생각이라고 보장하지 않는다. 명시 근거 없는 같은 화자의 여러 암묵적 흐름, 독립 표시 없는 주제/청자 전환, 0.3초 이후 뒤늦게 도착하는 완성형 보충은 여전히 모델/기존 후속 경로가 판단한다. 사용자가 다음 조각을 보낼지 예측할 수 없으며, 이미 송신한 답변을 삭제·재전송하지 않는다. typing 이벤트를 새 응답 권한이나 대기 연장의 근거로 도입하지 않았다.

전체639회귀 OK164.355초·새GPU7시퀀스7/7·실제 생성/SDK mock11송신·구성29원본/29조회. 같은 모델의 좁은 비교는 의미4→1회·후속 답변3→1회였다. 최초/마지막 조각 지연과 잔여 의미 결함은 PERFORMANCE-PIPELINE을 따른다.

최신 검사 결과는 아래 이전 기록과 구분해 [현재 상태](CURRENT-STATUS.md)와 [릴리즈 QA](RELEASE-QA.md)에 누적한다. 정정·우려·농담·전달문 질문의 기존 Gemma 의미 오류가 해결됐다고 주장하지 않는다.

## 실행 계약

`Runtime.ingest → Utterances → 기존 Conversations/SocialRouter → 공정 큐 → 최종 원본 검사`를 사용한다. 별도 대화 엔진이나 새 모델을 만들지 않는다. 운영 기본 모델·참여 계획·로더·GPU Worker는 유지한다.

Raw Message는 기존 불변 `Event`다. 실제 ID·작성자·서버·채널/스레드·reply·본문·시각을 가진다. 조립 결과는 `raw_parts`와 별도 `utt:` ID, 구성 개수에 따른 버전을 가진 Event 뷰다. 대표 원본은 최초 요청/명확한 호출의 실제 ID이며 내부 ID로 Discord에 답장하지 않는다. DialogueState에는 결합 문자열을 가짜 메시지로 넣지 않고 각 실제 원문을 따로 넣는다. 사회적 판정에는 결합 표현과 구성 원본 ID/화자/reply를 제공한다. 추정된 합류·청자 권한을 만들지 않는다.

## 결합과 대기

- 명확한 호칭만 있는 입력, 조사·연결 어미·방식 설명 등 문법적으로 미완성인 입력에서만 임시 버퍼를 연다. 완성형 직접 질문에는 고정 대기를 넣지 않는다.
- 서버·채널/스레드·작성자를 격리한다. 열린 미완성 발언이 있을 때만 다음 조각을 후보로 삼으며, 다른 사람 대상 근거·reply 전환·독립 요청 표시·새 명확한 요청은 경계로 처리한다. 다른 화자의 메시지는 그 버퍼를 끝내거나 내용에 들어가지 않는다.
- 보충 대기 기본 0.8초, 첫 조각을 버퍼에 넣은 때부터 최대 4초다. 다음 조각은 최대 기한을 연장하지 않는다. 시간은 확정 기한이며 청자/대화 선택의 근거가 아니다.
- 대기 버퍼 최대 64개, 버퍼당 본문과 출처 메타데이터 예산 8,000자 상당이다. 2/3/10개 같은 의미적 개수 제한은 없다. 예산/기한 경계에서는 기존 조각을 확정하고 새 입력을 별도 처리한다. 초과분을 조용히 잘라 결합하지 않는다.
- 같은 작성자의 애매한 주제 전환, 형태만으로 완성 여부를 알기 어려운 구어체는 완전한 의미 분할로 해결된 것이 아니다. 이 단계의 문법 신호는 청자 판정이나 응답 강제 규칙이 아니다. 모든 한국어 분할 방식·긴 간격·여러 암묵적 흐름의 정확한 결합을 보장하지 않는다.

2,000자를 넘는 결합 의미 입력은 기존 창을 늘리지 않고 앞900자/끝1,000자와 생략 표시를 전달한다. 마지막 현재 질문을 처음2,000자 뒤에서 잃지 않게 했으며 원본 전체는 따로 보존한다. 이 긴 분기의 입력 보존은 단위 검사로 확인했고 실제 GPU 의미 품질은 NOT VERIFIED다.

## 생성·원본·변경

생성 중 미완성 보충은 먼저 모은다. 해당 원본을 향한 이전 결과는 보충 대기 중 송신하지 않는다. 확정한 보충으로 기존 보충 경로를 갱신하며 독립 요청은 취소하지 않는다. 매 조각마다 GPU를 다시 시작하지 않는다. 이미 완료한 요청은 새 보충으로 다시 열지 않는다. Gateway/모델 전환의 기존 deferred 경로와 최초 요청의 180초 기한을 유지한다. 기존30초 보충 제한 때문에 미완료 요청이 유실되던 경로는 제거했다. 여러 보충 창의 누적 예산을 넘으면 기존 요청을 취소하지 않고 같은 대화의 다음 세그먼트로 큐에 보존한다.

원본 대표 ID·전체 구성 ID·버전은 요청에 고정된다. SDK 전송 직전에 모든 구성 메시지를 실제 채널에서 조회하고 작성자·채널·본문 일치와 최신 권한/요청 상태를 확인한다. 같은 원본을 중복 조회하지 않는다. 따라서 N개 조각의 최종 검증에는 최대 N개 원본 조회가 필요하며 실제 Discord 네트워크 비용은 미검증이다.

첫/중간/마지막 조각의 편집·삭제는 의존 중인 결과를 무효화한다. 대기 중인 전체 후보를 취소하거나 저장된 실제 이력을 수정하며, 새 내용을 추측해 재구성/자동 재생성하지 않는다. 이미 보낸 답변을 자동 삭제/재송신하지 않는다. 변경 표지는 본문 없이 180초 보존하며 과도한 표지는 안전 차단한다. 종료·범위 무효화·개인정보 변경은 대기 버퍼를 정리한다.

## 기억·예약과 개인정보

RAM 버퍼는 동의 없는 장기 저장 경로가 아니다. 기억은 기존 본인·서버별 동의와 민감정보 검사를 그대로 받으며 **모든 조각의 작성 시각**이 동의 이후여야 한다.

Companion schema 7의 `source_parts`는 실제로 저장하는 기억/예약의 원본 의존 ID만 저장한다. 본문·새 동의를 저장하지 않는다. 파생 자료와 같은 SQLite 트랜잭션에서 연결하고, 중간 조각 삭제도 파생 자료 삭제/예약 취소와 tombstone으로 전파한다. 재시작 후에도 재생성을 막는다. 자료 삭제/만료 시 고아 연결을 정리한다. 다중 턴 요약은 기존 실제 원본별 인덱스를 사용한다. 운영 DB에는 이번 검사로 마이그레이션을 실행하지 않았다.

기존 정정·우려·농담·전달문 질문의 모델 의미 누락을 이 기능이 해결했다고 주장하지 않는다. 조립 오류와 청자/계획/연결/전송 오류를 구분한다. 실제 Discord, 다른 Windows, 사용자 수동 화면과 장시간 실사용은 별도 NOT VERIFIED다.
