## 유지한 수정 — 실제 출처를 잃지 않는 제한된 창

`social_evidence.py`는 최신 실제 봇 답변과 그 원본 요청, 실제 reply가 지목한 메시지와 부모를 먼저 보존하고 남는 자리를 최근 실제 발언으로 채운다. 6개 frame 창·4개 직접 연결 창을 유지하며 없는/만료된 부모나 발언을 만들지 않는다.

이전에는 봇 답변이 RAM에 있어도 보충 발언이 많이 쌓이면 마지막6개/4개 슬라이스가 그 답변을 제외했다. 이후 토큰 예산 축약에서도 첫 발언을 무조건 지워 출처를 다시 잃을 수 있었다. 이제 예산 축약은 보호된 출처 외의 발언만 제거하고, 모두 보호된 상태에서도 예산을 넘으면 불확실한 입력으로 실패 처리한다. 480자 본문이 잘린 경우 `text_clipped`로 표시한다. 짧은 입력의 기존 원문·순서·필드는 유지한다.

또한 frame의 마지막 수신자는 임의로 선택한 sibling의 상태값 대신 **마지막 실제 봇 reply의 보존된 부모 작성자**로 계산한다. 병합된 이력과 sibling 상태가 다를 때의 합성 재현을 추가했다. 부모가 없으면 수신자를 지어내지 않는다. 이는 짧은 정정/전달문 의미 실패와 별개의 근거 불일치 수정이다.

## 독립 평가와 실제 GPU 검증

네 상황·여러 화자·두 독립 흐름을 포함한32문항을 결과 확인 전 고정했다. 두 후보 실험은 이 세트로 튜닝하지 않았다. 안정적인 기존 선택의 기준선과 최종 입력 보존 코드가 모두 **29/32**, 오개입0·누락3·연결0이었다. 정정·우려/농담·전달문 바깥 질문에서 각각1건 누락했다. 일반 의미 품질 향상을 확인한 결과가 아니다. 이후 이 세트는 회귀 자료로만 사용한다.

최종32건의 실제 GPU Worker 호출은28회, 큐 대기0, 판단/모의 텍스트 경로 p50/p95 **0.7500/1.3750초**였다. 실제 텍스트 생성 시간이 아니다. 기준선은 다른 모델 로딩 세션이므로 두 세션 간 차이를 속도 개선의 인과 근거로 사용하지 않는다. 최종 GPU manifest의 전체 소스 해시와 현재 소스가 일치함을 확인했다.

- **실제 GPU + 모의 그룹 상태 PASS:** 세 번의 종료 판단에서 활동 흐름 수1→1→0, 수신자별 engaged `[false,true]`→`[false,true]`→`[false,false]`. 다른 수신자의 진행 작업은 취소되지 않았다. 단일 Worker 호출3회. 실제 Discord 그룹 시험이나 사람의 자연스러움 판정은 아니다.
- **실제 생성→모의 전송 2/2:** 짧은 직접 호출2.890초/17토큰, 우려를 담은 후속6.250초/46토큰. 후속은 의미 판단1회+생성1회, 직접 호출은 생성1회로 총 Worker3회다. 혼합 p50/p95 4.570/6.082초는 2건의 보간값일 뿐 운영 지연 통계가 아니다. 실제 생성 TTFT는0.594/0.610초, 생성속도6.078/8.710tokens/s, 큐0·재생성0이었다. 이전의 다른 출력 길이와 속도 향상으로 비교하지 않는다.
- 정상 종료 세션은 allocated1024bytes·reserved2MiB, 종료 후 Worker0. 진단용 예외 재현 세션에서는 검증 도구의 bound generate 참조가 남아 종료 계측 때 가중치가 유지됐다. 해당 수치를 정상 unload 실패나 장시간 누수 인증으로 사용하지 않는다. 그 프로세스 종료 뒤 집계 VRAM도 모델 없는 수준으로 복귀했다. 로더·GPU 안전 기준·시스템 설정은 바꾸지 않았다.
- 최초 그룹 검증 도구는 비동기 완료 전 조회로 IndexError가 났고, CPU 점검에서는 legacy chooser가 같은 흐름을 재사용한 fixture 문제도 확인했다. 두 결과는 검증에서 제외·보존했다. 별도 실제 흐름 구성과 완료 대기를 CPU에서 확인한 뒤 수정된 GPU 검증만 PASS로 기록했다.
