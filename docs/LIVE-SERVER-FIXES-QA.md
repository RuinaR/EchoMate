## 실제 기능 상태의 읽기 전용 설명

`capabilities.public_state`가 현재 Settings, 해당 서버/채널의 허용 범위와 실제 송신 권한, 모델 준비/실패, 해당 작성자 본인의 동의, 해당 사용자 검색 실패를 공개 가능한 상태로 변환한다. 다른 사람의 동의·기억·관계, 토큰, 실제 경로, 내부 로그는 반환하지 않는다. 모델의 추정 ID로 조회하지 않는다.

알아들을 수 있는 기능 질문은 닫힌 사실 표현기로 짧은 한국어 반말을 만든다. 설명 자체의 추가 GPU 분류·생성·외부 조회는 없다. 기존의 대화 연결 판정은 별도로 실행될 수 있다. 기분의 가벼운 표현은 반영하지만 사실 답변을 임의 캐릭터 자유 생성으로 바꾸지 않는다. 일반 생성에는 같은 공개 상태의 압축 자료를 전달하며 기존 캐릭터 생성은 유지한다. 질문 표현 인식과 자유 생성의 일반화는 한계가 있다.

송신 직전 설정 revision·권한·원본 최신성을 검사하고, 기능 답변에는 본인 동의·모델 상태도 다시 조회한다. 달라졌으면 옛 설명을 보내지 않는다. 일시정지/금지 채널에서는 설명을 위해 송신 정책을 우회하지 않는다. 정확한 과거 무응답/지연 원인을 확인할 근거가 없으면 원인을 꾸며내지 않는다.

이번에는 원격 Application ID나 실제 명령 목록을 조회하지 않았다. 연결 승인 이후 소유자가 앱에서 `명령 목록 확인 · 정리`를 선택하면 현재 애플리케이션의 전역/서버별 명령 이름·종류와 변경안을 읽어 표시한다. 서버 범위는 현재 가입 서버와 관리/설정 서버의 합집합이며 조회 불가 범위가 있으면 실패한다. 과거 모든 탈퇴 서버의 명령까지 발견했다고 주장하지 않는다.

소유자가 표시된 계획에 `동의로 교체`를 입력해야 적용한다. 적용 직전 목록 fingerprint를 재검사하고, 다른 Application ID이면 거부한다. 현재 앱의 전역 명령을 `/동의` 하나로 교체하고 서버별 명령은 비운 뒤 실제 API 목록을 재조회해야 성공이다. 부분 실패 시 pending과 로컬 감사 기록을 유지하고 다시 검토한다. 과거 `command_sync_pending`만으로 시작 시 자동 실행하지 않는다. 다른 앱의 명령을 지우지 않는다.

[Discord 공식 Application Commands](https://docs.discord.com/developers/interactions/application-commands)의 애플리케이션별 전역/서버별 bulk overwrite 범위를 따른다. 실제 호출은 사용자 별도 승인 이후다. 오프라인 Check 경로는 검토·적용 두 명령을 모두 차단한다.
