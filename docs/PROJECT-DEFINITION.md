# EchoMate 프로젝트 정의서 — 현재 기준

## 2026-10-19 추가 — 구성원 호칭과 신원 경계

봇 이름 호출과 다른 구성원의 호칭 후보를 분리한다. 실제 Discord User ID·멘션·원본 reply를 우선하고 서버+채널별 근거로 후보를 판단한다. 동명이인·일반 명사·불확실한 별명을 임의 확정하지 않는다. 후보 누적은 당사자 동의와 실제 근거를 요구하고 소유자만 확인/수정/삭제한다. 추정 ID로 다른 사람의 기억·친밀도·알림 대상을 조회·갱신하지 않는다. 전체 회원 조회/새 Members Intent/추가 모델을 기본 비용으로 넣지 않는다. 실제 서버 QA는 현재 금지이며 로컬 모의·GPU 검증을 구분한다. [설계와 제약](MEMBER-ADDRESSING.md).

## 2026-10-19 최신 — 병렬 대화·릴리즈 근거

단일 GPU는 직렬 추론하되 대화·요청은 독립 관리한다. 같은 작성자의 연속 호출도 보충 병합/별개 요청 보존/원문 완전 중복 억제/FIFO를 구별하며 모든 응답은 고정 원본에 reply한다. 다른 사람의 호출로 기존 생성을 일괄 취소하지 않는다.

가장 최근 명시 지시는 전역 자율 참여 차단을 대체한다. 활성은 세션 수가 아니라 상호작용·대기·종료·휴지 상태로 계산한다. 다른 범위를 전역 차단하지 않고 신규 자율 진입만 활동 수준/범위별 쿨타임/부하로 보수적으로 조절한다. 직접 호출·기존 지속은 별도이며 중복/자원 한도는 유지한다.

소유자가 켠 자동 저장만으로 다른 구성원의 동의를 추정하지 않는다. 개별 허용·철회와 기존 자료 보존을 갖춘다. 기존 모델/사유 데이터/성별·캐릭터/기억·예약·기본 이모지·스티커를 유지한다. 멀티모달 확장은 제외다. 실제 Discord 다중 계정과 Windows 사용자 조작 증거 없이 전체 릴리즈 PASS를 선언하지 않는다.

## 2026-10-19 추가 — 지속 문맥·선택 기억·본인 예약

모든 앱 모델에 같은 호출/문맥/관계·장기 기억·예약 계층을 적용한다. 반응 및 관계가 권한·사실성·안전보다 우선하지 않는다. 자동 기억은 기본 OFF, 출처/시간/만료/조회 격리·본인 삭제를 갖춘다. 불확실한 시간·가상 요약을 실제 사실로 확정하지 않는다. 예약은 저장 성공 뒤 확인하고 GPU와 독립해 허용 범위에서 본인에게만 알린다. 임의 타인 호출·채널 우회·불명확 전송 자동 재발송은 하지 않는다. 소유자 관리 UI와 개인정보 제외 진단을 제공한다. 원본 corpus/개인 어댑터/기존 사용자 설정 보존, 새 학습·미디어 확장 없음.

## 2026-10-19 추가 요구 — 성인 유머와 공통 성별

기존 모델과 개인 LoRA를 보존하고 모델 선택지를 세 개로 확장한다. 성인 유머는 기본 OFF이며 공식 연령 제한 채널/부모 스레드에서만 비노골적이고 상호 원하는 농담을 허용한다. 실제 나이·동의는 채널 표식만으로 확정하지 않는다. 성별은 전 모델 공통 자기소개 설정이며 고정관념적인 말투를 강제하지 않는다. 품질 근거가 부족한 GGUF는 승격하지 않고 기존 기본 모델+정책 대안을 사용한다. 신규 참여 확률과 진행 중 대화를 분리하며 시간만으로 대화 종료를 확정하지 않는다. 멀티모달/등록 미디어 확장은 없다. 세부 구현과 실제 검증 구분은 [ADULT-MODE-QA](ADULT-MODE-QA.md)를 따른다.

## 2026-10-19 최신 요구 변경 — 아래 과거 제한보다 우선

**가장 최근 변경:** 등록 미디어 활용은 제거한다. 정상 인식/사용은 Unicode 이모지와 Discord STANDARD 기본 스티커로 제한한다. 커스텀/GUILD/기타 이미지·GIF 픽셀 분석은 기본 꺼짐인 실험 옵션 하나로 묶고 송신 허용을 확대하지 않는다. 이전 등록 미디어 요구와 구현은 폐기한 과거 기록이다. 초대된 서버의 채널/활성 스레드를 다크 GUI의 직접 구현한 목록에서 선택한다. 지연된 답변도 원래 질문의 Discord reply 대상으로 보낸다. 기능 제거가 기존 비공개 파일/학습 모델 삭제를 뜻하지는 않는다.

추가 사용자 요구에 따라 Windows GUI로 기분/활동 빈도/채팅과 이모지별 활동 범위를 조작하고 현재 처리 상태를 확인한다. 멘션은 응답의 유일한 조건이 아니다. 허용된 자율 범위에서 문맥에 맞게 참여하고, 이미 대화 중이면 새 참여 확률과 독립적으로 화자·대상·주제를 판단해 이어간다. 이는 무조건 발언하거나 모든 서버를 자동 활성화하는 요구가 아니다. 속도 개선은 실제 GPU 지연으로 검증하고 단일 측정을 보편적 성능으로 보고하지 않는다.

사용자의 명시적 요청으로 Bot의 실제 Discord 통합과 멀티모달 출력을 범위에 추가했다. 과거의 텍스트/Unicode 전용·thread 전용 제한을 현재 허용 서버의 명시적 채널/스레드 allowlist로 확장한다. 기존 학습/모델 품질 선정은 보존하며 이 변경은 모델 품질 승인이나 운영 서버 송신 승인이 아니다.

- 공식 Bot Token/Gateway, 소유자 Discord User ID 인증, 비공개 슬래시 응답/관리 패널, 서명된 로컬 설정.
- 별도 캐릭터 계층: 다정함75/귀여움40/장난기20, 반말, 자모 웃음/울음 기본 회피, 인용/코드/URL 비파괴. 7가지 수동 기분과 기본 비활성의 제한된 자동 연출. 실제 의식/욕구 주장 금지.
- 서버/채널/스레드별 허용 범위, 명시적 부모 상속, mention/autonomous/reaction/silent 모드. 기분과 활발함을 분리하고 기존 맥락/침묵/지속 코어를 재사용한다.
- 정상 사용은 Unicode 이모지와 Discord 공식 STANDARD 기본 스티커로 제한한다. GUILD 스티커/커스텀 이모지 송신과 등록 파일의 이미지/GIF 전송은 제거한다. 수신 미디어를 송신 자산으로 승격하지 않는다.
- 실제 이미지 픽셀과 다중 프레임을 로컬 모델로 분석하고 서버별 비공개 캐시에 저장한다. 이름만으로 시각 의미 추정 금지. Lottie는 현재 미지원.
- AI는 구조화된 행동 후보만 제안한다. 결정적 실행기가 설정/최신 상태/권한/에셋/승인/빈도/중복을 검사한다. 장애 시 침묵한다.
- 실제 서버 QA는 사용자가 설정한 테스트 서버에서만 수행한다. 모델과 데이터는 외부로 보내지 않으며 새 학습/운영 승격은 하지 않는다. 구현·모의 테스트·GPU 검사·실제 Discord QA 상태는 CURRENT-STATUS와 WORKLOG에 구분해 기록한다.

상세 사용법/권한/제약: [DISCORD-BOT.md](DISCORD-BOT.md). 기존 단일 화자 스타일 학습을 실제 대화 쌍으로 해석하지 않는 원칙은 유지한다.

## 최신 상태가 우선하는 범위

현재 로컬 Gemma 4 12B IT 개인 어댑터 300/2,500단계 학습 및 생성 A/B가 존재한다. 아래 초기 구현 상태 절은 과거 기록이다. 최신 상태는 `CURRENT-STATUS.md`, 근거·실험은 `ML-EXPERIMENTS.md`를 따른다. 사용자 요청에 따라 reviewed 자료에 한정한 추가 로컬 실험을 진행하며 새로운 데이터 원천·유료 서비스·운영 자동 승격은 포함하지 않는다.

단일 화자 원문은 독립 스타일 적응으로만 취급한다. 제작용 지시를 붙이더라도 실제 상대방 질문이나 실제 대화 쌍이라고 표시하지 않는다. 페르소나 품질은 생성·사람 평가로 판단하며 검증 loss와 분리한다.

## 목적
Discord의 지정된 채널·스레드에서, 선택한 페르소나의 말투·표현 습관을 반영하면서 현재 대화의 맥락에 맞게 참여하는 **명확히 식별되는 AI 봇**을 만든다.

## 2개 독립 프로그램
**EchoMate Studio (오프라인 제작)**
- 허용된 JSON/CSV/개인 데이터 자료의 형식·범위·품질 확인.
- 파일 안 작성자 목록/기간/메시지 수를 확인하고 당사자 동의·데이터 사용 조건을 충족한 페르소나만 제작(향후 기능).
- 스타일 분석 → 범용 모델 프롬프트 → 허용된 RAG → 선택적 QLoRA를 평가해 모델 아티팩트 생성.
- 데이터 기준일/해시/모델 버전/품질 평가를 저장. 새 자료로 다시 제작하더라도 이전 버전 보존과 롤백 지원.
- 봇 운영 도중 학습하지 않음.

**EchoMate Bot (온라인 추론 전용)**
- Discord 개발자 포털의 공식 봇 계정.
- 서버 닉네임/프로필 이미지(공식 API가 지원하는 범위에서) 설정, 준비된 로컬 모델 파일 선택·읽기 전용 로드.
- 허용 채널·스레드, 대화 참여 빈도, 쿨다운, 자율 발언, 중지·재시작 설정.
- Discord 현재 대화를 단기 문맥으로 이해하고 페르소나의 말투로 답변. 봇 자기 반응·중복·오래된 답변 방지.
- 기본 글자 및 Unicode 이모지만 출력. 첨부·GIF·스티커·커스텀 이모지 금지.
- 데이터 수집·파일 가져오기·학습·관계 프로파일링 기능을 봇 안에 넣지 않음.

## 데이터에 대한 확정 사항
- Studio는 **1개 이상의 JSON 파일을 개수 제한 없이 입력**받는다. **파일 하나 = 채널 하나**이며, 같은 사람의 여러 채널 기록을 한 페르소나의 자료로 합칠 수 있다. 처음 검증한 `messages1.json`, `messages2.json`은 그중 예시일 뿐 고정된 입력 요건이 아니다.
- 필드: ID, Timestamp, Contents, Attachments. 상대방 발언, 명시적인 reply_to나 채널 ID는 자료에 없음.
- 초기 2개 검증 파일의 고유 기록 304,997건, 필터 후 텍스트 후보 270,989건. 파일 수가 늘어나도 채널 간 연속 메시지는 묶지 않음.
- 시간상 인접 메시지는 같은 화자의 연속 발언 *후보*일 뿐 중간 상대 발언은 보이지 않음.
- 최근 기록의 스타일 비중을 높이며 반감기 후보 180/365/730일을 평가. 과거 말투를 전부 폐기하지 않음.
- 개인정보, 민감 내용, URL, 커스텀 이모지/미디어 텍스트 등은 처리 목적에 따라 필터.
- 개인 데이터 패키지를 분석할 수 있음과 AI 학습 허가 여부는 다름. 실제 학습은 사용 조건 확인 후.

## 초기 비목표
- Discord 서버 모든 대화의 무단 자동 수집/비공식 self-bot
- API 데이터 기반 사용자 간 영구 친밀도·관계 프로파일링
- 실시간 무검증 모델 가중치 업데이트, 유료 클라우드 모델 필수화
- AI 봇 신분 은폐, 여러 페르소나 동시 발언

## 현재 구현·검증
- JSON 메타데이터 분석기와 5개 단위 테스트.
- 사용자의 Windows PowerShell 테스트 5건 OK, 실제 두 파일 분석 report.json 생성 및 업로드 확인.
- 모델 학습·Discord 봇·UI·성능 평가·모델 캐시 관리 아직 미구현.

## 구현 완료 기준
- Studio: 허가된 자료를 재현 가능하게 버전 관리하고 데이터 편향/누수/안전을 검증.
- Bot: 허용된 곳에서만 발언, 중지 가능, 오류·네트워크 재연결/중복 방지, 로컬 모델만 추론.
- 품질: 기본 LLM 대비 페르소나 스타일 유사성 향상과 대화 문맥 적합성 검증.

## 2026-10-18 추가 확정: 메시지 이모지 반응
- EchoMate Bot이 사람의 메시지에 자율적으로 **Discord 기본 Unicode 이모지 반응(reaction)**을 달 수 있어야 한다.
- **일반 텍스트 발언과 완전히 별개의 활성화 토글·활동 채널/스레드 allowlist·반응 빈도(확률/쿨다운)** 설정.
- 자기 메시지·다른 봇·수신 거부 사용자·미허용 채널에는 반응 금지.
- Discord 커스텀 서버 이모지·스티커·GIF·파일은 사용하지 않는다.
- 현재 구현된 것은 Discord 네트워크 호출 전 단계의 순수 정책 게이트 `echomate_studio.reactions`; 실제 Discord 반응 API 연동은 추후 Bot 개발 단계.

## 2026-10-18 추가: 자율 발언은 언제든 침묵할 수 있어야 함
- 발언 빈도 설정은 대화를 시작/참여할 **기회**의 빈도이지 메시지 생성을 강제하는 비율이 아님.
- 높은 빈도라도 분위기가 무겁거나 민감한 상황, 추가할 내용 없음, 끼어들기 부적절함, 장시간 무대화 상태에서는 발언하지 않음.
- 발언 게이트는 활동 채널/스레드 범위, 사용 중지, 타 봇, opt-out, 쿨다운, 최근 사람 발언 시간, 현재 대화 상황 평가를 먼저 확인하고 마지막에 확률을 적용.
- 실제 문맥 평가를 생성하는 LLM/휴리스틱 모듈은 아직 구현 전. 현재는 평가 결과를 입력받아 침묵/허용을 결정하는 순수 모듈만 구현.
- 자동 이모지 반응 정책은 발언 판단과 별도 유지.

## 2026-10-18 — 대화 연속성 최우선 요구
- 봇이 끼어들기 전 현재 채널/스레드의 최근 대화 전체 흐름과 화자별 발언, 답장 관계를 파악해야 한다.
- 끼어든 뒤에도 봇 자신의 앞선 발언과 사람들이 보인 반응을 연결해 대화를 자연스럽게 이어가야 한다.
- 다른 채널/스레드의 맥락을 섞지 않는다. 일정 시간 오래된 기록은 단기 상태에서 소멸시킨다.
- 자율 발언 기회와 실제 개입 여부를 분리한다. 대화 중 화제가 바뀌거나 불필요할 때 침묵을 유지한다.
- 생성 중 새 메시지가 들어오면 예전 문맥의 답변을 그대로 게시하지 않고 폐기·재평가한다.
- 원문 대화는 로컬 단기 처리이며 타인 관계 프로파일링이나 장기 학습 데이터로 자동 누적하지 않는다.

## 2026-10-18 — 메모리 용량 요구
- 사용자 시스템 RAM 32GB. 좁은 40개 메시지/30분 제한 대신 더 긴 맥락을 허용하도록 **채널/스레드당 기본 500개 메시지, 24시간**으로 확장.
- 로컬 RAM에 유지하는 최근 대화 상태와 실제 LLM 호출 시 보내는 컨텍스트 길이를 분리. 현재 프롬프트 기본 16,000자 예산.
- 화제 연속성을 위한 선택적 장기 요약/기억 검색은 향후 사용자의 이용 범위·보존 설정과 결합해 설계. 서버 이용자의 메시지를 자동 영구 프로파일링하지 않음.

## 2026-10-18 — 실제 문맥 기반 참여 판단 시작
- 로컬 모델이 최근 화자별 메시지를 보고 민감 분위기·유의미한 기여·개입 적절성 세 조건을 평가한다.
- 판정 형식 오류나 Ollama 호출 실패 시 침묵 처리. 확률은 문맥상 참여해도 되는 기회에만 적용.
- 진행 중 대화의 연속성은 단기 대화 버퍼를 통한 문맥 전달로 시작하며, 의미적 주제 요약·장기 검색은 미구현.
- 문맥 평가기는 오프라인 프로브 및 단위 테스트까지 개발된 단계. 실전 발언 자동화는 미연결.
