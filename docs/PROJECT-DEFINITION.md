# EchoMate 프로젝트 정의서 — 현재 기준

## 2026-10-25 현재 제품 계약과 구현 경계

단일 사전 학습 캐릭터/한 GPU 모델, 별도 CharacterId·사용자 이름·epoch, 사용자별 동의/캐릭터별 기억·관계를 따른다. 현재 Lime concrete GGUF 및 opt-in Runtime/임시 DB 경계는 구현됐지만 기존 Windows 앱의 최초 활성화·설치 UI는 아직 연결 전이다. 기존 Gemma 설정은 자동 변경하지 않는다. 신규 모드 명령은 `/동의`·읽기 전용 `/캐릭터`, 기존 모드 `/성격`은 호환 유지한다. 아래 이전 일자 정의보다 이 전환 계약과 [최신 QA](CHARACTER-RUNTIME-INTEGRATION-QA.md)가 우선한다. 모델 품질 FAIL/파일·라이선스 BLOCKED 때문에 RELEASE BLOCKED다.

## 2026-10-25 사전 학습 캐릭터 선택 제품으로 전환

최신 사용자 요구에 따라 기존 '공통 Gemma + 편집 캐릭터/학습'을 제품 목표에서 대체한다. 개발자가 검증한 사전 학습 여성 캐릭터를 선택하며 전역 활성 캐릭터/GPU 모델은 각 하나다. 여러 사용자의 독립 대화·기억·동의·친밀도·예약·공정 큐는 유지한다. 캐릭터 ID/표시 이름/이름 버전/생성 epoch를 구분하고 전환 전 응답을 새 캐릭터로 송신하지 않는다. 기존 운영 Gemma 선택이나 개인 자료는 자동 변경하지 않으며 과거 기록은 legacy/연구로 보존한다.

초기 후보 Yaho/Lime/여성 IT 기획자는 모두 제품 Ready로 확정된 모델이 아니다. Yaho의 연구 목적 라이선스 제한, 기획자 저장소의 어댑터 파일 부재, 새 backend·기억 namespace·UI 통합이 차단 조건이다. [단계별 계약·재사용 감사·근거](PRETRAINED-CHARACTER-TRANSITION.md)가 아래 과거 제품 정의보다 우선한다. 실제 Discord 및 운영 DB 변경은 별도 승인까지 금지한다.

## 2026-10-24 실행·조회 결과의 최신성

실제 저장/예약 성공 안내와 명시 개인정보 목록은 송신 시점에도 해당 본인·범위·자료·동의 근거가 유효해야 한다. 조회한 빈 결과도 현재의 전체 부재를 무제한 확정하는 자료가 아니다. 철회·삭제·정정 뒤 오래된 파생 답변을 보내지 않으며, 모델이 말한 약속은 실행 영수증이 아니다. 인격 표현과 별개의 코드 검증으로 유지한다. [구현과 검증 범위](OPERATION-EVIDENCE-QA.md).

## 2026-10-24 가상 인격·표현 범위

캐릭터는 가상 배경·판단·관계·습관을 가진 편집 데이터다. 현실의 사용자 기억/실제 몸/함께한 경험을 꾸미지 않는다. 본인 동의·신원/Discord 권한·코드 출력 제한은 캐릭터보다 우선한다. 가벼운 독설/까칠한 비판은 설정과 현재 상호 요청에 따라 가능하며 불편 후 공격·괴롭힘·보호 특성 혐오·위협은 허용하지 않는다. 실제 사용자 기억과 가상 세계관은 같은 저장 대상으로 취급하지 않는다. [카드 구조/검사](CHARACTER-CARD-QA.md).

## 2026-10-24 캐릭터 및 Discord 명령 계약 갱신

공식 모델은 Gemma 4 no-LoRA 하나를 공유하고 캐릭터는 반응 관점·습관·말투가 다른 독립 데이터로 관리한다. 성격은 지속 성향, 7개 기분은 현재 표현 상태다. 사용자 정체성 자료가 개인정보·참여·행동 권한을 변경하지 못한다. 기존 프로필은 읽기 호환하며 무단 덮어쓰기하지 않는다.

일반 사용자의 개인정보 명령은 `/동의` 하나다. 추가 `/성격`은 실제 봇 소유자만 현재 적용 성격을 비공개 조회하는 읽기 전용 명령이다. 의도한 전역 등록 집합은 두 개이며 이전 한 명령 정책을 대체한다. 실제 Discord 조회/변경은 각각 별도 승인이 필요하고 비표시 문제와 사회적 판단 차단은 유지한다. [페르소나 구현·실제 평가](PERSONA-QA.md).

- 파일 안 작성자 목록/기간/메시지 수를 확인하고 당사자 동의·데이터 사용 조건을 충족한 페르소나만 제작(향후 기능).
- 스타일 분석 → 범용 모델 프롬프트 → 허용된 RAG → 선택적 QLoRA를 평가해 모델 아티팩트 생성.
- 데이터 기준일/해시/모델 버전/품질 평가를 저장. 새 자료로 다시 제작하더라도 이전 버전 보존과 롤백 지원.
- 봇 운영 도중 학습하지 않음.

**EchoMate Bot (온라인 추론 전용)**
- Discord 개발자 포털의 공식 봇 계정.
- 서버 닉네임/프로필 이미지(공식 API가 지원하는 범위에서) 설정, 준비된 로컬 모델 파일 선택·읽기 전용 로드.
- 허용 채널·스레드, 대화 참여 빈도, 쿨다운, 자율 발언, 중지·재시작 설정.
- Discord 현재 대화를 단기 문맥으로 이해하고 페르소나의 말투로 답변. 봇 자기 반응·중복·오래된 답변 방지.
- 기본 글자 및 Unicode 이모지만 출력. 첨부·GIF·스티커·커스텀 이모지 금지.
- 데이터 수집·파일 가져오기·학습·관계 프로파일링 기능을 봇 안에 넣지 않음.

## 데이터에 대한 확정 사항
- Studio는 **1개 이상의 JSON 파일을 개수 제한 없이 입력**받는다. **파일 하나 = 채널 하나**이며, 같은 사람의 여러 채널 기록을 한 페르소나의 자료로 합칠 수 있다. 처음 검증한 `messages1.json`, `messages2.json`은 그중 예시일 뿐 고정된 입력 요건이 아니다.
- 필드: ID, Timestamp, Contents, Attachments. 상대방 발언, 명시적인 reply_to나 채널 ID는 자료에 없음.
- 초기 2개 검증 파일의 고유 기록 304,997건, 필터 후 텍스트 후보 270,989건. 파일 수가 늘어나도 채널 간 연속 메시지는 묶지 않음.
- 시간상 인접 메시지는 같은 화자의 연속 발언 *후보*일 뿐 중간 상대 발언은 보이지 않음.
- 최근 기록의 스타일 비중을 높이며 반감기 후보 180/365/730일을 평가. 과거 말투를 전부 폐기하지 않음.
- 개인정보, 민감 내용, URL, 커스텀 이모지/미디어 텍스트 등은 처리 목적에 따라 필터.
- 개인 데이터 패키지를 분석할 수 있음과 AI 학습 허가 여부는 다름. 실제 학습은 사용 조건 확인 후.

## 초기 비목표
- Discord 서버 모든 대화의 무단 자동 수집/비공식 self-bot
- API 데이터 기반 사용자 간 영구 친밀도·관계 프로파일링
- 실시간 무검증 모델 가중치 업데이트, 유료 클라우드 모델 필수화
- AI 봇 신분 은폐, 여러 페르소나 동시 발언

## 현재 구현·검증
- JSON 메타데이터 분석기와 5개 단위 테스트.
- 사용자의 Windows PowerShell 테스트 5건 OK, 실제 두 파일 분석 report.json 생성 및 업로드 확인.
- 모델 학습·Discord 봇·UI·성능 평가·모델 캐시 관리 아직 미구현.

## 구현 완료 기준
- Studio: 허가된 자료를 재현 가능하게 버전 관리하고 데이터 편향/누수/안전을 검증.
- Bot: 허용된 곳에서만 발언, 중지 가능, 오류·네트워크 재연결/중복 방지, 로컬 모델만 추론.
- 품질: 기본 LLM 대비 페르소나 스타일 유사성 향상과 대화 문맥 적합성 검증.

## 2026-10-18 추가 확정: 메시지 이모지 반응
- EchoMate Bot이 사람의 메시지에 자율적으로 **Discord 기본 Unicode 이모지 반응(reaction)**을 달 수 있어야 한다.
- **일반 텍스트 발언과 완전히 별개의 활성화 토글·활동 채널/스레드 allowlist·반응 빈도(확률/쿨다운)** 설정.
- 자기 메시지·다른 봇·수신 거부 사용자·미허용 채널에는 반응 금지.
- Discord 커스텀 서버 이모지·스티커·GIF·파일은 사용하지 않는다.
- 현재 구현된 것은 Discord 네트워크 호출 전 단계의 순수 정책 게이트 `echomate_studio.reactions`; 실제 Discord 반응 API 연동은 추후 Bot 개발 단계.

## 2026-10-18 추가: 자율 발언은 언제든 침묵할 수 있어야 함
- 발언 빈도 설정은 대화를 시작/참여할 **기회**의 빈도이지 메시지 생성을 강제하는 비율이 아님.
- 높은 빈도라도 분위기가 무겁거나 민감한 상황, 추가할 내용 없음, 끼어들기 부적절함, 장시간 무대화 상태에서는 발언하지 않음.
- 발언 게이트는 활동 채널/스레드 범위, 사용 중지, 타 봇, opt-out, 쿨다운, 최근 사람 발언 시간, 현재 대화 상황 평가를 먼저 확인하고 마지막에 확률을 적용.
- 실제 문맥 평가를 생성하는 LLM/휴리스틱 모듈은 아직 구현 전. 현재는 평가 결과를 입력받아 침묵/허용을 결정하는 순수 모듈만 구현.
- 자동 이모지 반응 정책은 발언 판단과 별도 유지.

## 2026-10-18 — 대화 연속성 최우선 요구
- 봇이 끼어들기 전 현재 채널/스레드의 최근 대화 전체 흐름과 화자별 발언, 답장 관계를 파악해야 한다.
- 끼어든 뒤에도 봇 자신의 앞선 발언과 사람들이 보인 반응을 연결해 대화를 자연스럽게 이어가야 한다.
- 다른 채널/스레드의 맥락을 섞지 않는다. 일정 시간 오래된 기록은 단기 상태에서 소멸시킨다.
- 자율 발언 기회와 실제 개입 여부를 분리한다. 대화 중 화제가 바뀌거나 불필요할 때 침묵을 유지한다.
- 생성 중 새 메시지가 들어오면 예전 문맥의 답변을 그대로 게시하지 않고 폐기·재평가한다.
- 원문 대화는 로컬 단기 처리이며 타인 관계 프로파일링이나 장기 학습 데이터로 자동 누적하지 않는다.

## 2026-10-18 — 메모리 용량 요구
- 사용자 시스템 RAM 32GB. 좁은 40개 메시지/30분 제한 대신 더 긴 맥락을 허용하도록 **채널/스레드당 기본 500개 메시지, 24시간**으로 확장.
- 로컬 RAM에 유지하는 최근 대화 상태와 실제 LLM 호출 시 보내는 컨텍스트 길이를 분리. 현재 프롬프트 기본 16,000자 예산.
- 화제 연속성을 위한 선택적 장기 요약/기억 검색은 향후 사용자의 이용 범위·보존 설정과 결합해 설계. 서버 이용자의 메시지를 자동 영구 프로파일링하지 않음.

## 2026-10-18 — 실제 문맥 기반 참여 판단 시작
- 로컬 모델이 최근 화자별 메시지를 보고 민감 분위기·유의미한 기여·개입 적절성 세 조건을 평가한다.
- 판정 형식 오류나 Ollama 호출 실패 시 침묵 처리. 확률은 문맥상 참여해도 되는 기회에만 적용.
- 진행 중 대화의 연속성은 단기 대화 버퍼를 통한 문맥 전달로 시작하며, 의미적 주제 요약·장기 검색은 미구현.
- 문맥 평가기는 오프라인 프로브 및 단위 테스트까지 개발된 단계. 실전 발언 자동화는 미연결.

## 2026-10-18 최신 추가 요구
- AI 응답 생성 시간이 길 때 새 메시지를 감지하고 흐름 변화에 맞춰 재평가·재생성하며 무한 재시도 금지. Discord 전송 직전 최종 상태 확인.
- 인터넷 검색은 필요한 최신 사실 질문에 한해 선택적으로 수행하며, 사용자가 활성화/해제 가능한 옵션, 쿼리 개인정보 최소화 및 출처 확인 필수.
- 페르소나 제작을 다음 우선 작업으로 전환: 다중 JSON 채널 입력의 최근 가중치 기반 스타일 분석 → Qwen 기본/스타일 적용 A/B → 학습 허가 확인 시 QLoRA 평가.
