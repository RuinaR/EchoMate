## 2026-10-20 준비 상태

아래 절차는 소스 체크아웃의 현재 UI를 사용자가 직접 확인하기 위한 것이며 이번 차수에서 창을 열거나 사용자 화면을 자동 조작하지 않았다. 현재 Portable은 저장소 src보다1개 누락·4개 차이가 있으므로 두 버전의 확인 결과를 혼합하지 않는다. 오프라인 UI 확인은 사회적 대화 품질이나 정식 릴리즈 승인이 아니다. 최신 [판단 구조 검증](SOCIAL-EVIDENCE-QA.md)은 BLOCKED이며, 실제 Discord는 계속 금지/미검증이다.

자동 검사만으로 확인하기 어려운 실제 글자 가독성·키보드 이동·파일 선택창·창 크기·사용 흐름만 확인한다. 아래 확인을 아직 사용자가 수행한 것으로 기록하지 않는다. 정식 릴리즈 승인이 아니다.

## 먼저 안전하게 시작

1. 기존 EchoMate가 켜져 있으면 **직접 종료**한다. 다른 앱이나 게임을 종료할 필요는 없다. GPU 모델을 두 번 로딩하지 않도록 한다.
2. 일반 실행 파일 대신 **`EchoMate-Check.vbs`**를 더블클릭한다. 이 항목은 사용자가 직접 실행하는 절차다. 자동 검사의 자체 창 표시 실수와 정정은 별도 QA 기록에 남겼다.
3. 창 제목에 **오프라인 검증 · 운영 자료와 분리됨**이 있는지 확인한다. 이 창에는 실제 Bot Token을 넣지 않는다.
4. **처음 사용 안내**의 등록창에서 미리 채워진 가상 사용자 ID와 가짜 토큰을 그대로 적용한다.

검증 자료는 `%LOCALAPPDATA%\EchoMate\manual-check`에 저장한다. 기존 운영 `local_data`와 다르다. 창에는 **가상 서버·가상 채널**만 표시하며, 봇 켜기와 목록 새로고침은 실제 연결을 차단한다. 일반 `EchoMate.vbs`는 운영 실행 파일이므로 이번 확인에 사용하지 않는다.

## 확인 목록

- [ ] **처음 사용 안내**: 무엇을 입력하는지 읽기 쉽고, 입력란의 토큰이 가려진다.
- [ ] **대화할 곳**: 가상 채널과 스레드를 고를 수 있다. 채팅·이모지 설정을 바꾸면 미저장 표시가 나타나고 저장 뒤 사라진다.
- [ ] **AI 모델**: 모델 폴더 선택창을 열고 취소해도 설정이 바뀌지 않는다. 보유한 검증된 분할 모델을 고르면 파일 검사와 실제 준비 상태가 구별된다. 모델 파일을 이동·삭제하지 않는다.
- [ ] **성격과 기분**: 캐릭터를 복제해 이름·말투를 바꾸고 저장한다. 가져오기/내보내기는 새 테스트 파일명을 사용하며 기존 파일을 덮어쓰지 않는다. 취소했을 때 원래 값이 유지된다.
- [ ] **표현 고급 설정**: 슬라이더를 끌거나 방향키로 바꾸고 길이·비속어 버튼을 선택한다. 적용 후 다시 열어 값을 확인하고, 다음에는 값을 바꾼 뒤 닫아 원래 값이 유지되는지 확인한다. 버튼·목록의 hover/누름/선택/키보드 포커스를 구분할 수 있어야 한다.
- [ ] **로컬 미리보기**: 개인정보 없는 짧은 합성 질문 하나를 보낸다. 준비·처리 표시와 답변을 확인한다. 창을 닫고 GPU 정리가 끝날 때까지 기다린다. 로딩 중 취소는 약25초 걸릴 수 있으며 즉시 물리 중단을 뜻하지 않는다.
- [ ] **사람·기억·예약**: 자료가 없는 상태를 오류나 연결 대기로 오해하지 않게 안내한다. 이 검증 창에는 실제 사용자 자료가 없어야 한다.
- [ ] **진행 상황**: 실제로 수행한 모델 준비·미리보기와 오류를 구분해 보여 준다. 오프라인에서 **봇 켜기**를 누르면 연결 차단 안내가 나오며 실제로 접속하지 않는다.
- [ ] **사용성**: 평소 Windows 배율에서 작은 창·큰 창을 확인한다. 글자가 겹치거나 버튼이 잘리지 않고, Tab·Enter·Esc·스크롤이 예상대로 동작한다. Windows 배율 변경은 사용자가 원하는 경우에만 한다.
- [ ] **종료·복원**: 검증 창을 닫고 같은 `EchoMate-Check.vbs`로 다시 연다. 검증용 설정·프로필이 유지되고 운영 자료는 나타나지 않는다.

모델 준비가 자원 부족으로 거절되면 그 안내를 기록하고 중단한다. 페이지 파일이나 GPU 안전 설정을 바꾸거나 반복 재시도하지 않는다.

## 친구 서버 시험 준비 — 별도 승인 전 실행 금지

이 목록은 사용자가 나중에 실제 접속을 명시적으로 허용한 뒤 직접 진행할 계획이다. 현재 자동 연결·인증·송신·명령 동기화는 하지 않았다.

1. 별도 테스트 채널 한 곳만 허용하고 다른 채널은 침묵으로 둔다. 테스트 스레드를 쓰면 상속/개별 허용 범위를 확인한다. 처음에는 신규 자율 참여를 낮게 둔다.
2. 참여자에게 로컬 PC 저장 위치와 `/동의`의 관계·기억·요약 개별 기본 OFF를 설명한다. 처음에는 동의 OFF와 합성 주제로 진행하고 개인 일정·민감한 이야기·타인 정보를 입력하지 않는다. 다자 요약은 모든 참여자의 동의가 필요하다.
3. 두 명이 각각 봇을 부르고 원본 답장 대상이 맞는지 본다. 한 명이 완성형 반응 3~5개를 나눠 보내고, 다른 두 명이 서로 이야기해도 봇이 사람 간 대화를 가로채지 않는지 확인한다.
4. 봇에게 질문→우려/정정/농담→다른 사람에게 청자 전환을 시험한다. 직접 호출·후속 누락·오개입·말하는 중 조기 답변·중복 답변을 각각 기록한다. 의도적인 삭제/수정은 테스트 메시지만 대상으로 한다.
5. 이상하면 Windows 앱에서 **봇 끄기**를 누른다. 재시작 전에 허용 채널을 침묵으로 되돌린다. 강제 종료나 운영 자료 초기화로 해결하려 하지 않는다.
6. 대략적인 시각, 발언 조각 수, 원래 의도한 청자, 기대/실제 동작만 적는다. 진행 상황의 무응답 사유와 **개인정보 없는 진단 저장**을 사용한다. 운영 소스 실행은 `local_data/bot/diagnostic-report.json`, Portable은 해당 사용자 데이터 저장소의 `bot/diagnostic-report.json`을 확인한다. 경로는 앱 안내를 우선한다.
7. 원문·토큰·DB·개인 이름/ID·모델 경로가 담긴 자료를 공개 업로드하지 않는다. 진단 파일도 공유 전에 확인한다. 친구 서버 시험은 사용자 평가이며 장시간 안정성/다른 PC/정식 릴리즈 승인과 구분한다.
