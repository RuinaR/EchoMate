# 동의 기반 다중 턴 대화 요약

2026-10-19 후속 릴리즈는 최대160자 개인 발췌와 별개의 **다중 턴 압축 기록**을 추가한다. 기존 발췌/기억/관계/예약/설정은 보존한다. CompanionStore의 스키마5→6은 새 요약·참여자·출처 인덱스·요약 전용 삭제 표식 테이블을 추가한다. 기존 운영 DB를 개발 검증 목적으로 마이그레이션하지 않았다.

## 기억 계층

| 계층 | 자료·목적 | 수명 |
| --- | --- | --- |
| 현재 RAM 원문/활성 세션 | 실제 메시지·작성자·reply와 현재 대화 이해 | 기존 RAM 정책, 재시작 시 소멸 |
| 소유자 허용 개인 장기 기억 | 종류별 취향/계획/일시 상태 | 기존 종류별 만료/보류·삭제 정책 |
| 관계 통계 | 교류 집계, 친밀도 연출 | 대화 내용을 대체하지 않음 |
| 과거 개인 발췌 | 이전 버전의 짧은 자기 서술 | 기존30일 정책으로 보존·구별 |
| 다중 턴 요약 | 주제/질문/당시 답변/정정/결정/계획/미해결/종료와 실제 출처 | 30일, 갱신·철회·삭제·출처 변경 검사 |

## 생성과 저장

입력은 실제 RAM 대화의 최근 최대40턴이며 토큰화한 문맥 상한 안에서 오래된 부분을 더 줄일 수 있다. 없는 화자나 발언을 만들어 넣지 않는다. 참여자·시각·원본 메시지 ID와 실제 답장 관계를 로컬 모델에 제공한다. 민감정보/확인되지 않은 제3자 멘션을 포함한 입력은 보수적으로 제외한다. 정상적인 봇 멘션·인용 게임명은 입력에서 이해하되 인용문을 실제 사건으로 확정하지 않는다.

기존 base 가중치가 최대5개 항목으로 압축한다. 항목은 종류·한국어 요약·출처 ID·검증용 원문 연속 부분을 포함한다. 애플리케이션은 출처 존재와 실제 원문 부분의 일치를 검사한다. 검증용 원문과 전체 대화는 영속 요약에 저장하지 않고 압축 내용과 출처 연결만 보관한다. **연속 원문 일치가 모든 바꿔 쓴 내용의 의미적 진실성을 증명하지는 않는다.** 최신 정정 우선·당시 봇 답변의 사실성 미보증을 생성 지시와 사용자 안내에 포함한다. 제한된 GPU 정정 사례를 통과했지만 임의 장문 대화의 요약 완전성/환각을 인증하지 않는다.

영속 저장은 관련 대화의 **모든 사람 참여자가 이 서버의 요약 저장에 동의**한 경우만 한다. 동의 버전/선택 시각과 source 시각을 실제 DB 쓰기 트랜잭션에서 다시 확인한다. 과거에 동의하지 않은 시기의 발언을 새 동의로 소급 저장하지 않는다. 한 사람의 동의로 타인의 사적 대화를 저장하지 않는다. 혼합 동의 대화에서 본인이 현재 채널의 요약을 명시적으로 요청하면 RAM에서 일시적으로 답할 수 있지만 영속 저장하지 않는다.

`is_history_request`는 과거 대화 회상과 단순 새 질문을 로컬 의미 판정으로 구별한다. 시간/회상 후보 신호는 모델 호출 비용을 줄이는 입구이며 모든 한국어 변형을 포괄한다고 보장하지 않는다. 현재 채널에서 실제 참여한 본인의 요약만 조회한다. 다른 사용자 ID/다른 채널 자료를 선택하지 않는다. 후보 요약 검색에는 제한된 키워드 관련도와 최신 시각을 사용하므로 모호한 장기 회상의 정확성은 추가 평가가 필요하다.

자료가 없으면 ‘확인할 내용이 없음’, 관계 집계만 있으면 내용 요약 자료와 다름, 저장 자료가 있지만 동의가 바뀌면 활용 중지로 설명한다. 교류 자체가 없었다고 단정하지 않는다. 요약의 source URL/실제 사실성은 대화 보존과 별개다.

## GPU·취소·수명

매 메시지마다 추가 요약을 만들지 않는다. 자동 요약은 설정이 ON이고 대화가 종료/휴지 상태이며 사용자 작업·GPU 대기가 없을 때만 우선순위3으로 한 건 예약한다. 새 입력·설정 변경·연결 해제·모델 전환·동의 변경·종료 시 취소한다. 예약 알림 처리는 요약 GPU를 기다리지 않는다. 백그라운드 생성에서도 backend 자원 실패 시 런타임을 안전 정지하고 이유를 기록한다. 봇이 OFF이면 생성하지 않는다. 최근100대화의 성공 버전은 새 발언 없이 다시 생성하지 않으며, 시도 지문과5분 간격으로 반복 실패를 억제하고 대기·모니터 기록도 제한한다.

직접 회상 요청은 원래 사용자 요청의 공정 큐와 원본 reply를 사용한다. 이미 저장된 요약이 있으면 다시 생성하지 않는 경로가 있다. 미리 만든 자료가 없는 명시적 요약은 긴 생성이 될 수 있으며 이번 GPU 다자 사례는 약41~43초였다. 자동 작업은 사용자의 새 요청을 위해 중단하지만 명시적 요약을 일반 짧은 응답과 같은 속도라고 주장하지 않는다.

저장 뒤 source 삭제/수정은 해당 요약을 무효화한다. 요약 삭제는 별도 표식을 남겨 같은 source의 대기 생성이 부활하지 않게 한다. 이 표식은 다른 종류의 기억/알림을 대신 삭제하지 않는다. 동의 철회는 기존 자료 삭제와 다르며 자동 활용은 중지한다. 개인 삭제/전체 관리자 초기화는 참여자/출처 인덱스와 캐시/대기 작업을 함께 처리한다. 전송 직전에도 동의 버전·요약 존재/만료·현재 대화를 다시 확인한다. 만료 자료는 조회에서 제외하고 정리 주기에 삭제한다. 원본 자료나 운영 DB를 개발자가 일괄 삭제한 것은 아니다.

## Windows 관리

‘기억 관리→검색·종류→대화 요약’ 또는 ‘사람과 관계→대화 요약 보기’에서 대상 사용자의 다중 턴 기록을 선택한다. 내용·source·갱신/만료 시각·현재 활용/동의 상태를 확인하고 선택 삭제/요약만 초기화할 수 있다. 기존160자 발췌는 ‘기존 발췌 보기’로 구별한다. 봇 OFF에서도 DB를 조회하며 오래된 비동기 결과는 새 선택을 덮어쓰지 않는다. 만료 자료는 정리 후 목록에서 사라진다. 내용이 손상된 요약은 정상 기억처럼 쓰지 않고 관리 가능한 오류 항목으로 표시한다.

코드/DB/취소/동의 회귀와 숨긴 Tk 목록/출처/삭제 연결, 실제 GPU 다자 정정 및 저장된 자료의 재조회/채널 격리를 검증한다. 실제 Discord·사용자 화면 조작·장기 품질은 미검증이다. 결과와 재현은 [후속 QA](FOLLOWUP-RELEASE-QA.md)를 따른다.
