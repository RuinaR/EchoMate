2. `CharacterNames`는 구형schema1을 쓰지 않고 읽고, 명시적 저장 시schema2의 캐릭터별 NameVersion을 원자적으로 기록한다. 동일 이름 저장은 version을 올리지 않고 저장 실패는 이름/version 모두 보존한다. GGUF의 현재 이름/version stamp는 await 뒤에도 확인해 늦은 답변을 거절한다. 기존 CharacterModelManager epoch·취소·동의/기억/예약 경계는 유지한다. 운영 이름 파일은 변경하지 않았다.
3. 실제 대화에서 미동의·미조회인데 카페 공동 경험의 기록에 접근했다고 주장하거나, 조회하지 않고 기록이 없다고 단정했다. 명확한 과거 기억 확인 질문은 `lookup_inquiries`에서 Runtime의 미조회/미허용/실패/빈 성공/무효화 상태에 따라 응답한다. found는 기존 검증된 근거 생성 경로를 유지한다. 이 한정된 입력 요청 문법은 한국어 주장 추출기나 운영 출력 금칙어 필터가 아니다. 인용/조건/제안/기억 저장 요구를 실행하거나 차단하지 않는다. **평서형 유도·혼합 질문·일반 자유 생성의 모든 허위 기억과 약속은 미해결이다.**
4. 로컬 명령의 조회 상태가 기존 `command`로 뭉쳐져 있었다. `/기억 목록`·`/알림 목록`의 실제 영수증과 실패 상태를 found/empty/failed로 반영한다. 조회 실패를 빈 목록으로 바꾸지 않고 저장/예약 명령은 조회 미실행으로 표시한다.
