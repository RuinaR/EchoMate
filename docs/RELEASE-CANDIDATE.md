## 자동 운용 중 무응답 원인

제공된 비공개 진단의 마지막 요청들은 TEXT 선택/생성까지 진행한 뒤 `duplicate_or_rate_veto`였다. 같은 날짜의 운영 ledger에는 성공 전송이 **100건**, 설정된 일일 한도도 **100건**이었다. 큐 실행/대기는 0이었으며 안전 정지도 아니었다. 이 자료는 일일 상한 소진을 뒷받침하며 GPU 교착을 뒷받침하지 않는다. 개별 과거 요청의 전체 원문/수신 상태를 복원했다는 뜻은 아니다.

## 제한된 공식 인터넷 근거

기본 OFF. discord.py는 공식 PyPI 배포 JSON, Transformers는 해당 GitHub 저장소 최신 release, Python은 CPython 최근 태그, Minecraft는 공식 manifest, LoL은 공식 DataDragon 버전 목록만 읽는다. Python 태그/LoL 데이터 버전을 실제 서비스 최신 배포와 동일시하지 않도록 답변에 한계를 명시한다. 처음 discord.py GitHub releases 경로는 404여서 공식 PyPI로 변경했다.

일반 뉴스·가격·법률·임의 제품·임의 URL 검색은 **미지원**이다. 이 경우 확인 불가라고 답한다. 지원하지 않는 기능을 수행한 척하거나 출처 URL을 생성하지 않는다. 응답 URL은 해당 조회에서 검증된 출처 또는 현재 사용자 입력 URL만 허용한다. 사용자가 준 URL을 인용할 수 있다는 것은 내용을 검증했다는 의미가 아니다.

고정된 HTTPS 엔드포인트만 허용하고 리다이렉트/환경 프록시/임의 URL 접속을 막는다. 7초·1MiB 제한, 성공 10분/실패 30초 캐시, 주제별 동시 요청 병합을 적용한다. 자료를 실행 지시로 사용하지 않으며 필요한 버전 문자열만 스키마 검증한다. 고정 URL이므로 개인정보 검색어 외부 전송을 회피하지만 범용 공개 질문의 검색 요구 전체를 충족하지는 않는다. ## 성능과 릴리즈 판정

일일 상한 소진 후 낭비되던 GPU 생성을 앞에서 차단하고, 확정 코드 작성/반응/검증 버전 조회는 불필요한 텍스트 생성을 생략한다. 권한 확인은 5초 캐시를 재사용하지만 전송 직전에는 강제로 다시 조회한다. SDK mock에서 반복 5회 읽기가 1회 조회, 마지막 전송에서 추가 1회 조회인 것을 확인했다. 실제 네트워크 지연 개선율은 측정하지 않았다.

출력 정책 old/new 비교는 같은 가중치·합성 문항·greedy·768 최대 토큰·교대 순서와 워밍업 분리로 실행했다. 정책만 넣은 생성은 대체로 더 느렸으며 이를 속도 향상이라고 부르지 않는다. 명확한 작성 요청의 런타임 우회와 모델 직접 생성 측정은 구별한다. 제한된 사실 문자열/코드 검사 통과는 사람 평가나 포괄적 정확성의 증거가 아니다.

최종 판정은 **로컬 릴리즈 후보 / 전체 실사용 NOT VERIFIED**다. 실제 Discord 등록·송수신·권한/rate limit·장시간 GPU/RAM·사람 블라인드 품질은 미검증이다. 새 학습·모델 승격·운영 설정 초기화·개인자료 외부 전송은 없다. 원본 진단·응답·성능·임시 DB·소스 스냅샷은 `local_data/release-qa-20261019/`에만 보관한다.
