# 캐릭터 행동·기분·현재 성격 조회 QA

## 2026-10-24 후속 평가 기반 정리

이후 공개 대화 원천·독립 소비 장부·응답 전용 블라인드/근거 ID 검사 도구를 구축했다. 새 출처 계약은 일부 예시 혼동을 줄였으나 개인 사실 조작/기억 약속이 남아 기각했다. 기존 인격/카드·`/성격`/명령 승인 경계를 변경하지 않았다. 새로운 실제 생성192응답과 기존 회귀 자료, 자동/사람 평가를 [후속 QA](DIALOGUE-EVALUATION-QA.md)에 구분했다. 정식 릴리즈 BLOCKED는 유지한다.

## 2026-10-24 범위와 원인

시작은 main/로컬·원격 `601c572` clean이다. 실제 Discord 인증·조회·등록·삭제·동기화·송신은 하지 않는다. 기존 `/동의` 비표시 원인은 여전히 미확정이며 정식 릴리즈는 **BLOCKED**다. 이번 명령 계약은 사용자 최신 요청에 따라 일반 사용자 `/동의`와 소유자 조회 전용 `/성격` 두 개다. 아래 구현 완료와 실제 클라이언트 복구는 별개다.

기존 compiler는 에너지·표현의 구간별 지침이 중심이고, 고민/반박에 무엇부터 반응하는지는 약했다. `character.instruction`에 있던 별도 다정함/장난기 지침과 프로필 유머 지침이 서로 다른 구간을 사용해 충돌할 수 있었다. 미리보기는 Runtime의 `effective_character`와 달리 자동 기분 처리를 거치지 않았고, 동의 없는 관계를 임의 50으로 표현했다. 입력 누락이나 잘린 프롬프트라고 가정하지 않고 실제 생성 입력과 GPU 응답을 비교했다.

## 구현 계약

- v2 프로필은 기존 값과 7개 기분을 보존하며, 반응 접근 방식·호기심·전제 점검·취향·가치관·대화 습관을 추가한다. v1은 원본 서명을 검증한 뒤 메모리에서 변환한다. 읽기만으로 파일을 다시 쓰지 않는다. 저장·가져오기·내보내기는 동일한 검증/원자 저장 경로를 쓴다.
- 성격은 반응의 내용과 순서, 기분은 에너지/문장 리듬에 적용한다. 다정함·귀여움·장난기는 하나의 compiler로 해석한다. 동의 없는 관계는 `None`이며 친분을 꾸미지 않는다. 동의된 친밀도는 접근 권한이 아니다.
- 공감/놀이/분석/건조한 직설 프리셋은 편집 가능한 설정 초기값이다. 별도 모델이 아니다. 사용자 소개·취향·가치관·습관은 길이를 제한한 JSON 자료이며 정책/권한 지시로 실행하지 않는다. 고정 대화 예시를 추가한 별도 후보는 아래 실험에서 기각했으며 최종 compiler에는 포함하지 않는다.
- 캐릭터 정책은 답변 생성에만 적용한다. 사회적 청자 분류·Action 권한·개인정보·코드 출력 제한·단일 GPU 큐·분할 로더와 메모리 안전 기준은 유지한다. 인물처럼 허위 경험을 주장하는 방식으로 차별화하지 않는다.
- 편집 중 값/저장된 미적용 프로필/현재 적용 프로필을 구분해 미리볼 수 있다. 네 프리셋 비교는 같은 질문·한 backend·동일 공정 큐를 순차 사용한다. 미리보기는 Runtime 입력이 아니며 관계·기억·예약을 갱신하지 않는다. 종료/취소 소유권과 정리를 유지한다.
- `/성격`은 실제 소유자 User ID를 검사하고 조회 시점의 적용 설정만 ephemeral Embed로 보낸다. GPU·개인 저장소를 조회하지 않으며 모델 미로딩 상태에도 handler가 동작한다. 설정 기분과 자동 기분의 발언별 연출을 구분한다. 비공개 경로·식별자·credential 형태는 표시 자료에서도 생략한다. Discord 기본 역할 권한은 미설정이며 실행 권한은 handler의 소유자 ID 검사다. 명령 이름이 일반 사용자 목록에 보일 가능성과 내용 접근은 별개다.
- 동기화 검증은 정확한 두 명령의 type/contexts/integration_types/default permissions를 확인한다. 명령별 접근 정책도 승인 fingerprint에 포함하며, 이전 한 명령 승인으로 새 계약을 적용할 수 없다. 전역 재조회 성공 전 서버별 구형 명령을 지우지 않는 기존 보호는 유지한다.

## 평가 방법

이전 실행 소스의 프롬프트를 변경 전에 비공개로 고정했다. 동일 Gemma 4 no-LoRA 분할 가중치·결정적 디코딩·공통 캐릭터 표시 이름·동일 질문·한 상주 모델로 기준과 후보를 비교한다. 출력/실제 metric/프롬프트 토큰 수를 보관하며 새 후보의 기대 행동은 생성 전에 고정한다. 취향이나 슬라이더 숫자가 다르다는 이유만으로 차별성을 PASS 처리하지 않는다.

평가는 공감 우선/비유와 놀이/원인·조건 분석/현실 점검이라는 반응 전략, 자연스러움, 정확성, 이전 응답의 접근 유지, 피곤한 기분에서도 정체성 유지로 구분한다. 해결책을 원하지 않는 사람에게 분석형이라는 이유로 조언을 강요하지 않는다. 자동 형식 검사·Codex의 이름 가린 정성 검토·사람의 블라인드 선호 평가는 각각 다른 근거다. 사람 평가는 **NOT VERIFIED**다.

첫 후보: 변경 전 12응답과 추상 행동 지침 32응답을 생성했다. 고민/의견 충돌에는 공감과 분석의 일부 차이가 있었지만, 장난과 건조한 유머가 일반적인 위로로 수렴했고 인사도 비슷했다. 네 캐릭터가 다른 사람처럼 느껴진다는 목표는 **FAIL**로 기록한다. 명료한 행동 예시가 없는 문제를 확인하기 위한 짧은 고정 예시 후보를 한 차례 추가 비교했고 첫 평가를 새 독립 자료로 재분류하지 않는다.

## 실행 및 근거 보관

비공개 결과는 `local_data/persona-20261024/`에 두고 업로드하지 않는다. 공개 도구는 `tools/verify_persona_gpu.py`이며 `--protocol`, `--baseline`, `--output`은 `local_data` 아래 새 경로를 사용한다. `--candidate-only`는 기준을 불필요하게 재생성하지 않는 비교 모드다. GPU 전 시스템 전체 가용 자원과 기존 shard admission을 확인하고 실제 InstanceLease를 소유한다. 실제 Discord HTTP와 aiohttp는 실패하도록 차단한다. `--runtime-protocol`은 같은 상주 모델을 재사용하는 SDK 모의 통합 검사다. 빌린 backend의 close는 모델 해제 근거가 아니며 최상위 finally의 해제 값을 확인한다.

표적 회귀는 `PYTHONPATH=src;tests;tools`에서 `python -m unittest test_persona_profiles test_ui_workflows test_command_recovery test_command_sync_payload -q`를 사용한다. 실제 Windows 사용자 입력이나 다른 앱의 화면은 조사하지 않는다. 격리 렌더링은 소유한 비활성 Desktop의 대상 HWND만 캡처한다.

### 짧은 고정 예시 후보 — 기각

첫 결과를 본 뒤 서로 다른 상황의 짧은 반응 예시를 compiler에 넣은 후보를 한 번 비교했다. 기존4질문16응답은 개발/회귀이고, 새5질문20응답은 생성 전 기대를 고정한 미사용 평가였다. 새 농담 요청에서 분석형이 상대의 지능을 깎아내리는 출력을 생성했다. 일부 재치 증가를 모욕·과장과 상쇄하지 않으며 후보를 **REJECT**했다. 인사/위로도 유사했으므로 예시는 제거했다. 이36응답과 실패 근거는 보존하며 최종 후보 성능으로 합산하지 않는다. 평가를 본 뒤 같은 질문으로 재튜닝하지 않았다.

최종 `character.py`, `character_profiles.py`, `runtime.py`, `inference.py`, `desktop.py`의 SHA256은 첫 GPU 실행의 봉인과 일치한다. 새로운 UI/스키마/조회와 충돌 제거는 유지하지만 **네 캐릭터가 완전히 다른 사람처럼 느껴지는 품질의 완료 판정은 보류**한다. 후속은 사람의 가린 비교·수용 기준 확인 후 별도 persona 대화 자료/관계·장기 턴 평가를 검토한다. 추가 모델/LoRA 학습/다운로드는 실행하지 않았다. 보상 없는 프롬프트 반복 실험으로 더 진행하지 않는다.

### 자원과 실제 생성·SDK mock
