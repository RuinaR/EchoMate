1. v4의 거짓 약속과 별도로, 실제로 실행한 저장/예약의 성공 안내가 송신 시점에도 유효한지 재현한다. 개인정보·실행 사실·해결 가능성이 높아 첫 우선순위로 선정했다.
2. 코드가 만든 실행 근거와 본인 동의 epoch/관계 입력을 기존 최종 fresh 경로에서 확인한다. 새 저장소·모델·schema 없이 정상 요청과 다른 사람의 작업은 보존한다.
3. 자유 생성의 모든 사실을 판정하려 하지 않고, 기능 구현/상태/실행 완료/미래 약속만 검사하는 좁은 평가자를 별도 교정한다. 이전 광범위 인격/사실 공동 평가자의 실패를 재사용해 합격 처리하지 않는다.
4. 교정 실패 시 판별기 연결/재작성/동일 prompt 튜닝을 중단하고, 독립적으로 실제 Runtime·SDK의 근거 보호를 검증한다. 정상 네 캐릭터의 입력/출력이 바뀌지 않았는지도 확인한다.
5. 마지막 공통 구조 전체 회귀·배포 후보/manifest·운영 자료 보존·문서·Git 마감. 실제 `/동의` 문제는 별도 승인 경계로 유지한다.

## 조사와 채택 근거

- [SQLite isolation](https://www.sqlite.org/isolation.html)·[WAL](https://www.sqlite.org/wal.html): 쓰기 transaction 안에서 변경 행과 consent version을 포착하고, 송신 직전 **새** 읽기 transaction으로 비교한다. 긴 read transaction을 계속 붙들면 과거 snapshot만 보므로 그렇게 구현하지 않는다. DB commit과 원격 Discord 완료를 하나의 원자 transaction으로 만들 수 있다는 주장은 하지 않는다.
- [FActScore](https://arxiv.org/abs/2305.14251): 자유 답변 전체를 한 점수로 처리하기보다 근거별 주장을 나누는 평가 접근을 참고한다. 이 연구의 성능은 EchoMate에서 검증한 수치가 아니다.
- [MiniCheck 논문](https://arxiv.org/abs/2404.10774)·[공식 구현](https://github.com/Liyan06/MiniCheck): 문서에 대한 제한 주장 검증이라는 비교 방향을 참고한다. 별도 가중치/의존성을 도입하거나 코드를 복사하지 않는다. 한국어 발화행위·실행 약속의 적합성은 별도 검증이 필요하다.
- [평가 설계 공개 자료](https://www.anthropic.com/research/demystifying-evals-for-ai-agents): 코드 결과와 모델 평가를 구분한다. 검증되지 않은 자동 점수나 높은 문장 유사도를 인격·사실성 채택 근거로 쓰지 않는다.

## 실제 재현과 원인

시작 소스에서 임시 SQLite/실제 Runtime의 세 회귀가 **3/3 실패**했다. 기억을 저장한 직후 삭제해도 ‘저장 완료’, 알림을 예약한 직후 취소해도 ‘예약 완료’를 모의 송신했다. 관계 동의를 생성 도중 철회해도 이전 관계 값으로 생성한 답변이 송신됐다.

`companion.handle_request`는 commit 후 문자열만 돌려줬고, 최종 fresh는 그 문자열의 실행 결과 행을 검증하지 않았다. 기존 `memory_guard`는 조회한 기억 행에만 적용됐다. 기능 질문의 닫힌 안내와 실험용 TwoStage에는 일부 상태 검증이 있었지만 기본 자유 생성의 본인 동의/관계 snapshot은 보호되지 않았다. Settings revision·원본 edit/delete·허용 범위 보호는 이미 있어 재구현하지 않는다.

제한 환경의 첫 비동기 재현은 출력 없이 정체돼 해당 프로젝트 테스트 세션만 중단했다. 기존 Windows 비동기 테스트와 같은 권한 환경에서 재현 결과를 확보했다. 이를 GPU/제품 자체 오류로 집계하지 않는다.

## 채택 후보: 실제 코드 실행 근거

`operation_receipts.py`의 불변 Receipt는 실제 저장 transaction에서만 만든다. 기억 행/동의 version, 예약의 실제 ID·작성자/채널·시각·상태·내용·원본 등 필요한 필드를 보존한다. 모델은 Receipt를 작성하거나 ID·청자·권한을 지정할 수 없다. 근거는 요청 RAM에만 있고 새 DB/장기 기록/프롬프트/일반 로그에 저장하지 않는다.

기존 `add_memory/extract/forget_memories/reserve_reminder/change_reminder`의 선택 인자로 근거를 받는다. 기본 호출은 기존 API 결과를 유지한다. Runtime의 명시 요청만 근거를 수집하고 마지막 transport fresh에서 새 read snapshot으로 검증한다. 삭제·정정·재동의·예약 취소/변경·만료·저장소 오류면 오래된 성공 문장을 보내지 않는다. 예약의 내부 preflight/backoff 시각만 바뀐 경우는 정상 안내를 취소하지 않는다. commit 오류 시 수집 중이던 근거를 비워 성공 대신 기존 실패 안내를 사용한다.

기억의 완료/취소 분기에서 실제 행을 제거했는데 저장했다고 말하던 문구도 완료·취소 반영 안내로 구분한다. 송신 전 무효화는 기존 UI의 취소 상태와 원인별 한국어 진단으로 표시하며 일반 모델 오류 횟수를 늘리지 않는다. at-most-once ledger의 보수적 failed_or_uncertain 표시는 유지한다. 불확실 송신을 자동 재생하거나 이미 보낸 메시지를 삭제하지 않는다.

`PrivacyStore.subject_snapshot`은 본인/서버의 세 동의 항목 epoch(꺼진 항목 포함)와 허용된 관계 값만 한 read snapshot으로 읽는다. 기본 자유 생성 전과 송신 직전에 대조한다. 철회 후 재동의는 이전 응답의 권한이 아니며 다른 사람/서버의 변경은 독립 요청에 영향이 없다. 초기 일시 조회 오류 뒤 개인 상태를 읽는 데 성공한 경우에도 최종 보호가 빠지지 않게 한다. 기존 기억 행 guard와 진단 우선순위는 보존한다.

생성 prompt·캐릭터 compiler·Lorebook·추론 횟수·사회적 청자/Action·원본 reply·DB schema는 변경하지 않는다. 이는 모델의 거짓 미래 약속/허위 공동 경험을 의미적으로 판별하는 기능이 아니다.
