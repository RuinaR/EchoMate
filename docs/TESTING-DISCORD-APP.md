# 새 앱 테스트 방법

## 공통 기억·예약 시험 (2026-10-19)

1. 앱 재실행 후 허용 테스트 서버/채널을 확인한다. 별칭을 저장하고 전체 이름/호격·인용/다른 대상에서 구별되는지 본다.
2. 한 번 답한 뒤 멘션 없이 후속 질문한다. 다른 사람에게 말하거나 대화를 종료하면 불필요하게 이어가지 않아야 한다.
3. 기본 OFF 기억 자동 저장을 원할 때만 켠다. 본인 취향·명확한 날짜 약속을 말하고 기억 관리에서 출처/현지 날짜/만료를 확인한다. 본인 기억 삭제/옵트아웃 후 재저장되지 않는지 본다.
4. 허용 테스트 채널에 실제 멘션으로 `1분 뒤에 테스트 알림이라고 알려줘`를 새로 보낸다. 예약 확인 후 본인 멘션1회가 와야 한다. 조회·시간/본문 수정·취소는 예약 알림 화면에서 확인한다.
5. 범위 밖, 타인 호출, 모호한 시각, 생성 중 수정/삭제/모델 전환은 차단/확인/취소되어야 한다. 불명확 송신 실패의 무작정 재시도를 기대하지 않는다.

실제 완료: 테스트 채널 예약 확인·1분 배달1회 및 사용자 도착 확인, GPU 작업 중 예정+1.936초. 다른 채널 불일치는 초기 수신0의 원인이었으며 채널을 바꿔 재시험했다. Windows 화면 직접 조작/전 모델 실서버 긴 대화는 미검증이다. 전체328검사/실제 GPU·모의 QA는 공통 문서 참조.

## 추가 확인 — 세 모델·성별·성인 유머 (2026-10-19)

앱 재실행 후 성격과 기분에서 모델 세 개와 성별 세 개를 확인한다. 성별을 저장하고 모델을 바꾼 뒤 재시작해 유지되는지 확인한다. 성인 유머는 현재 기본 Gemma 4+정책 대안이다. 새 GGUF는 실사용하지 않는다.

1. 테스트용 허용 채널에서 각 모델로 멘션 → 멘션 없는 후속 질문 → 다른 사람의 질문 → 다른 사람끼리 대화 → 종료 → 새 멘션을 시험한다. 모든 메시지에 응답하는 것은 성공 기준이 아니다.
2. 생성 중 새 메시지/삭제/모델 변경을 시험해 오래된 답변과 중복 발송이 없는지 확인한다. 준비 실패 시 기존 선택을 유지한다.
3. 성인 참여자와 동의가 확인된 별도 연령 제한 테스트 채널에서만 비노골적 농담을 시험한다. 일반 채널에서는 같은 선택이라도 일반 대화 정책이어야 한다. 시험 때문에 운영 채널의 연령 설정을 바꾸지 않는다.
4. 불편 의사·미성년 자기소개·특정인 모욕·비동의 요청은 농담을 중단하거나 거절해야 한다. 채널 표식은 나이/동의 인증이 아니며 규칙만으로 모든 위해를 검출한다고 보장하지 않는다.
5. 창 크기/DPI 배율에서 성별과 세 모델 버튼이 잘리지 않는지 직접 확인한다. 현재 숨긴 Tk 렌더링 경계 시험과 사용자 화면 관찰은 구분한다.

새 코드의 실제 Discord 송수신과 사람 블라인드 평가는 별도 확인이 필요하다. 상세 결과와 로컬 블라인드 파일 위치는 [ADULT-MODE-QA](ADULT-MODE-QA.md)를 따른다. 토큰/응답/평가 키는 공유하거나 Git에 넣지 않는다.

## 콘솔 창 수정 확인 (2026-10-19)

1. 기존 앱을 닫고 **EchoMate.vbs**를 더블 클릭한다. .cmd 대신 vbs를 사용해야 시작 단계의 콘솔도 피할 수 있다. 토큰/setup은 다시 입력하지 않는다.
2. 설정 변경 → 봇 켜기 → 허용 테스트 채널에서 멘션 → 긴 답변의 GPU 상태 점검 구간을 확인한다. 검은 콘솔 창이 반복해 열리지 않아야 한다.
3. 봇 끄기와 다시 켜기도 확인한다. 계속 보이면 어느 단계인지와 사용한 실행 파일명만 알려 준다. 토큰/메시지 원문은 필요 없다.

Windows 자식 프로세스에 콘솔이 없는 것은 명령 기반으로 검증한다. 실제 앱 화면 관찰은 사용자가 수동으로 확인한다. 최초 인증을 위한 PowerShell 설정창은 정상이다.

## 이번 변경 먼저 시험하기 (2026-10-19)

1. 열려 있는 기존 앱을 닫고 `EchoMate.cmd`로 다시 연다. 테스트 서버를 고른 뒤 **이 서버의 봇 이름 → 변경**에서 원하는 이름을 저장한다. 토큰이나 setup은 다시 입력하지 않는다.
2. 꺼진 상태의 전체 목록에서 테스트 채널만 허용하고 봇을 켠다. 실행 중에는 설정한 채널/상속 스레드만 나타나야 한다. **전체 목록 · 활동 설정**으로 나머지를 보고 돌아올 수 있어야 한다. 명시적으로 차단한 스레드는 기본 활동 목록에서 빠져야 한다.
3. 예를 들어 이름을 `별빛봇`으로 저장했다면 멘션 없이 `별빛아 안녕`을 보낸다. 허용 채널에서 자연스럽게 답하는지, 다른 서버에 그 이름이 적용되지 않는지 확인한다. 허용하지 않은 채널에서는 이름을 불러도 조용해야 한다.
4. 다른 사람을 부르는 상황/인용된 이름/동명이인도 시험한다. 오해했을 때 `너 말고 다른 사람 부른 거야`라고 정정하고 짧게 인정하거나 불필요한 추가 응답을 멈추는지 확인한다. 이름 후보는 의미 판단을 추가하므로 멘션 빠른 경로보다 느릴 수 있다.
5. 닉네임 표시가 바뀌지 않으면 봇의 **자기 닉네임 변경** 권한을 확인한다. 앱의 이름 설정과 Discord API 변경 성공은 구별한다. 진행 상황에서 진단 저장을 사용할 수 있다. 실제 개인 메시지는 보고서에 첨부하지 않는다.

새 기능은 모의 통합/Windows Tk 테스트까지 완료했고 실제 Discord 별명/호칭 QA는 남아 있다. 아래의 ‘현재 앱은 닫힌 상태’ 등은 이전 단계 기록이다.

현재 앱은 닫힌 상태로 두었다. 토큰/사용자 설정을 다시 입력하거나 setup을 덮어쓸 필요가 없다. **운영 서버 대신 허용한 테스트 서버의 채널 1개**부터 시험한다. 아래 문장은 합성 예시이며 개인 메시지를 복사할 필요가 없다.

## 1. 앱 열기와 대화할 곳 선택

1. 저장소의 `EchoMate.cmd`를 더블 클릭한다. ‘봇이 꺼져 있어요’는 정상이다. 모델을 켜기 전에도 서버/채널/진행 중인 스레드 목록을 불러온다. 목록이 없으면 ‘새로고침’을 누른다.
2. **대화할 곳**에서 테스트 서버와 채널을 선택한다. 처음에는 채팅을 **멘션·이어지는 대화만**, 이모지를 **대화 중에만 반응**으로 고른 뒤 **선택한 1곳에 저장**한다. 선택만으로는 설정되지 않는다.
3. **응답 방식**에서 **글로 답하기**와 **이모지로 가볍게 반응하기**를 켠다. 기본 스티커는 우선 꺼 두고 각각 확인한다. **실험 기능**의 이미지 분석은 꺼 둔다.
4. **봇 켜기**를 누른다. 응답도 함께 허용된다. 첫 모델 준비는 약 35~40초이며 PC 상태에 따라 더 걸릴 수 있다. 준비 중에는 시작 버튼이 비활성화돼 중복 모델을 로드하지 않는다. ‘Discord에 연결됨’을 확인한다.

예상: 별도로 선택하지 않은 채널은 활성화되지 않는다. 서버 전체를 켰다고 모든 채널에서 말하지 않는다. 보관된 스레드는 전수 조회하지 않으며 현재 접근 가능한 진행 중인 스레드를 표시한다.

## 2. 빠른 답장과 처리 상태

Discord에서 실제 봇을 멘션해 `안녕. 한 문장으로 인사해 줘.`라고 보낸다. **진행 상황**에서 작성 단계/경과/대기 요청/최근 답변 시간을 확인한다. Discord에서는 작성 중에 입력 중 표시가 나타나며, 완료 텍스트는 질문에 **답장**으로 달린다.

명시적 멘션의 단순 텍스트는 불필요한 참여 판단 없이 한 번 생성한다. 자모 표현 재생성이나 스티커 선택 등은 추가 호출이 생길 수 있다. 측정한 잡담은 약6초였지만 모든 질문의 시간 보장은 아니다. 앱 시작 로딩과 실제 답변 시간을 구별한다.

## 3. 멘션 없이 이어가기

첫 답변이 끝난 다음 두 가지를 각각 확인한다.

- 봇 답변에 Discord **답장**으로 `방금 이야기의 주제를 한 문장으로 알려 줘.`를 보낸다. 실제 이력으로 확인한 봇 답장이므로 새 참여 확률을 뽑지 않고 답한다.
- 답장을 받은 뒤 일반 메시지로 같은 주제의 후속 질문을 보낸다. 멘션이 없어도 봇에게 이어지는 질문과 주제 지속이 확인되면 답한다. 다른 사람끼리의 대화나 종료 인사는 조용히 넘어갈 수 있다.

**성격과 기분**에서 먼저 참여하는 정도를 ‘조용함’으로 바꾼 뒤 같은 흐름의 후속 질문도 확인한다. 이미 하던 대화는 신규 참여 확률과 별개다. 새로운 대화에도 먼저 끼어들게 하려면 해당 채널을 **자연스럽게 대화에 참여**로 저장한다. 매 메시지에 반응하지 않는 것은 정상이며 무작위 도배로 시험하지 않는다.

## 4. 오래 걸리는 답변과 원래 질문 연결

1. 멘션과 함께 `파이썬의 얕은 복사와 깊은 복사를 중첩 리스트 예시로 설명해 줘.`를 보낸다.
2. 아직 작성 중일 때 같은 사람이 30초 안에 `예시는 짧게 부탁해.`를 멘션 없이 덧붙인다.
3. 오래된 생성이 취소되고 추가 문맥을 반영한 최종 답변 하나가 **처음 질문의 답장**으로 달리는지 확인한다. 처음 답변이 이미 끝난 뒤 보낸 메시지는 새 후속 질문으로 처리된다.

원래 질문이 삭제되거나 권한이 사라지면 안전하게 취소해야 한다. 다른 사람의 메시지를 원래 멘션으로 추정하지 않는다. 입력 중 표시는 실제 응답 시간을 줄이는 기능이 아니며 취소 뒤 잠시 남을 수 있다.

## 5. 이모지·기본 스티커·실험 기능

- 이모지만: 테스트 채널의 채팅을 **대답하지 않기**, 이모지를 **어울릴 때 가볍게 반응**으로 저장하고 멘션과 함께 축하할 합성 상황을 보낸다. 텍스트를 보내지 않고 Unicode 반응만 하거나 필요 없으면 조용히 있는지 확인한다. 시험 뒤 채팅 설정을 복원한다.
- 기본 스티커: **응답 방식**에서 Discord 기본 스티커를 켜고 `기본 스티커로 안녕 인사해 줘.`라고 멘션한다. 공식 STANDARD 팩만 사용하며 서버 전용 스티커는 보내지 않아야 한다. 이 항목은 아직 실제 송신 QA가 필요하다. Discord가 전송을 거절하면 같은 에셋을 반복 시도하지 않아야 한다.
- 실험 OFF: 작은 테스트 이미지를 붙이고 내용을 물어본다. 실제 이미지를 본 것처럼 설명하지 않고, 이미지 분석 단계가 실행되지 않아야 한다.
- 실험 ON: **실험 기능**에서 이미지 내용 분석을 켜고 작은 합성 그림1개를 시험한다. 분석 시간이 추가되는지 확인한다. ON이어도 커스텀 이모지/서버 스티커/등록 이미지/GIF를 전송하지 않아야 한다. 시험 뒤 OFF로 돌린다. Lottie 픽셀 분석은 미지원이다.

등록 미디어 메뉴와 `/echo media_add`, `/echo media`는 없어야 한다. Discord 슬래시 명령 목록 갱신은 봇 연결 후 동기화된다. 예전 private 파일은 기능 제거와 별개로 보존했다.

## 6. 일시정지·종료·허용 범위

- 상단 **응답 허용**을 끄면 현재 생성을 취소하고 발언을 멈춘다. GUI의 일시정지는 이미 받은 대화 이력을 유지하며, 멈춘 동안의 새 메시지는 수집하지 않는다. **응답 재개**는 모델을 다시 로드하지 않는다.
- **봇 끄기**는 연결/모델을 종료하고 실행 중 대화 이력을 정리한다. 다음에 켤 때는 다시 로딩한다. 재시작 후 영구 기억을 기대하지 않는다.
- 설정하지 않은 채널/스레드에서는 멘션해도 응답하지 않는지 확인한다. 일반 사용자는 관리 명령/설정을 바꿀 수 없어야 한다. 실제 다른 계정 검증은 아직 별도 QA다.

## 문제가 있을 때

‘어떤 설정 / 어떤 동작 / 기대한 결과 / 실제 결과 / 대략 몇 초’만 알려 주면 된다. **토큰·서명 키·개인 메시지 원문은 보내지 않는다.** 상태/성능은 `local_data/bot/desktop-status.json`, 종료 후 `desktop-performance.json`, 비공개 진단은 같은 폴더에 있다. 앱을 다시 열기 전에 이전 창/봇이 종료됐는지 확인한다. 설정을 직접 편집하면 서명이 깨질 수 있다.
