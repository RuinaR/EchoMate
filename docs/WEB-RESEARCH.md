# 공개 근거 검색 — 무료·무계정 경로

2026-10-19 후속 릴리즈 구현. 기존 버전5주제 조회는 그대로 빠른 경로로 남긴다. 일반 사실/출처 질문은 별도 `web_research.py`와 `safe_web.py`를 사용한다. 앱의 인터넷 근거 검색은 기존 선택을 보존하며 기본 OFF다. 실제 Discord 접속 없이 검증했다.

공식 RSS 대안도 조사했지만 특정 제공자의 제한된 최신 피드를 범용 검색이라고 대체하지 않았다. Google/Bing/Discord 화면 우회 스크래핑이나 계정 생성은 없다. 법률·가격·제품 최신 정보 등 모든 공개 질문을 안정적으로 해결하는 범용 검색은 아직 인증하지 못했다. **무료 경로의 검색 범위와 실제 서비스 가용성 한계는 릴리즈의 미완료 항목**이다.

## 실제 처리 경로

명확한 기존 버전 조회는 고정 공식 API로 처리한다. 그 외에는 기존 로컬 Gemma base 가중치로 잡담/의견/현재 문맥/안정 지식/검증/최신성/전제/불확실의 짧은 제약 라벨을 고른다. 필요할 때만 공개 주제어를 별도 추출한다. 사용자가 분명히 근거 확인을 요구하면 안정 지식이라는 이유로 검색을 생략하지 않는다. 이 분류는 완전하지 않으며 유한 문항의 로컬 평가다.

잡담·의견·현재 대화 기억은 외부 검색으로 보내지 않는다. 원문 대화/기억/관계/ID를 외부 생성 모델에 전송하지 않는다. 공개 주제어만 사용하고 알려진 서버 이름 후보·별명·호칭, 긴 ID·토큰·연락처·민감정보 패턴을 발견하면 외부 전송을 막는다. 이 검사는 보수적인 방어이며 알려지지 않은 모든 개인 식별 표현을 완전 탐지한다는 보장은 아니다. 공급자는 최소 검색어와 접속 IP를 볼 수 있다.

위키 검색은 최대3개 후보에서2개 원문을 확인한다. 가능하면 해당 원문에 실제 연결된 허용 공식 정부/기술 문서 링크를 추가로 읽어 우선한다. 뉴스는 최대5개 후보 중3개 원문까지 시도한다. 원문을 읽지 못한 제목만으로 사실을 확정하지 않는다. 위키 수정 시각, 기사 게시/수정 메타데이터, 수신 시각을 구별한다. 게시일을 찾지 못하면 없는 값을 만들어내지 않는다.

로컬 모델이 원문을 바탕으로 짧게 답하고 각 주장에 자료 번호를 붙인다. 또 한 번의 로컬 제약 판정으로 지지/충돌/부족을 검사한다. 애플리케이션은 실제 수신한 URL만 자료 번호와 함께 표시하며 모델이 생성한 URL은 허용하지 않는다. 긴 응답을 중간 문장에서 잘라 보내지 않는다. 자료가 없거나 충돌·검증 실패이면 확인하지 못했다고 안내한다. **모델의 근거 판정은 수학적 사실 보증이나 사람 검토를 대체하지 않는다.**

## 보안·성능 경계

HTTPS/443만 허용하고 사용자 정보 포함 URL·IP URL·로컬 호스트를 거부한다. 실제 소켓 연결의 DNS resolver에서 모든 주소의 public/global 여부를 검사하여 사설 IP와 DNS 변경 공격을 방어한다. 리다이렉트와 환경 프록시를 사용하지 않는다. 요청8초·원문1MiB, 전체 자료 탐색20초 제한이다. HTML은 실행하지 않고 script/style 등을 제외한 텍스트만 로컬 모델에 제공한다. 일반 기사 원문은 robots 규칙 확인 실패/거부 시 읽지 않는다.

비신뢰 자료 속 명령은 실행하지 않는다. 모델에는 API 실행 권한이나 로컬 파일 권한을 부여하지 않는다. 출처 판정과 Discord 행동 검증은 분리한다. 서버별 사유 문맥은 검색 캐시에 넣지 않고 공개 자료만 최대32개/5분 보관하며 robots 규칙 캐시도64개/1시간으로 제한한다. SDK/session/connector/resolver는 취소·오류에도 닫는다. 오류 유형만 진단하고 원문 검색어를 일반 로그에 기록하지 않는다.

GPU는 기존 공정 큐를 사용한다. 검색 분류에는 추가 지연이 있으므로 OFF일 때 새 분류를 하지 않고, 명확한 반응/코드 작성 안내는 검색 분류도 생략한다. 공개 원문 수신을 기다리는 동안 다른 대화의 GPU 작업과 예약 알림은 독립적으로 처리된다. 고정 버전 조회와 범용 근거 경로의 속도·정확도를 한 지표로 혼합하지 않는다.

## 실행 증거

실제 무계정 한국어 위키 검색/원문2개 수신은 약2.703초였다. 뉴스 실제 요청2회는 시간 초과였고 실패로 보존했다. 검색/캐시·잘못된 데이터·출처 번호·비공개 검색어·공개 DNS 검사는 mock/SQLite와 구별해 기록한다. 저장된 실제 공개 원문을 사용한 로컬 GPU 독립 평가에서 세 앱 모드 모두 계획4개/다중 턴 요약/근거 답변을 통과했다. 이는 라이브 뉴스 질의 성공이나 모든 주제의 일반화 성능이 아니다. 상세 수치는 [후속 QA](FOLLOWUP-RELEASE-QA.md)를 따른다.
