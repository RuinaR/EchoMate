## 처리 경계

1. 허용 범위와 실제 채널 접근 권한을 먼저 확인한다. Discord 메시지에서 제공된 작성자·닉네임·표시 이름·실제 멘션·같은 채널의 원본 답장 관계만 입력한다. 다른 채널의 referenced message를 청자 근거로 받아들이지 않는다.
2. `MemberDirectory`는 `(guild, channel, user)` 단위로 관측한 이름을 관리한다. 봇 호칭은 기존 `naming.name_address`가 담당한다. 구성원 후보는 별도이며 실제 멘션/답장과 혼동하지 않는다.
3. 정확한 이름, 제한된 접미사 제거, 한국어 호격/조사, 세 글자 한국어 성명에서 흔한 성씨 생략, 소유자가 확인한 별명으로 후보를 만든다. 세 글자 이상 호격의 한 글자 편집/전치 오타는 낮은 근거의 후보만 만든다. 임의 부분 문자열을 확정하지 않는다.
4. 고유한 구성원 호격이나 실제 타인 답장이 봇을 향한 명시적 호출과 충돌하지 않으면 생성 없이 침묵한다. 일반 명사와 구별하기 어려운 단독 이름, 동명이인, 공유 별명, 오타는 보류한다. 봇과 사람의 확인된 별명이 겹치면 봇의 확정 호출로 강제하지 않는다. 실제 봇 멘션은 별도 근거다.
5. 나머지는 기존 로컬 의미 판단에 발화행위와 별도의 구성원 근거를 전달한다. 후보만으로 대화를 합치지 않는다. 그룹 반응/주제 지속/독립 질문/종료는 기존 의미 계층이 판단하며 문장부호는 필수 조건이 아니다.
6. 승인된 응답만 기존 작성자 FIFO→공유 대화 FIFO→단일 GPU→채널 송신 검증으로 진행한다. 원본 메시지 reply·중복 방지·취소·범위·소유자 설정은 유지한다.

`speaker`는 실제 작성자 ID, `addressee`는 확인된 메타데이터 또는 충돌 없는 호칭의 청자 근거, `mentioned_people`은 실제 멘션 ID, `reply_target`은 원본 메시지 ID, `reply_author`는 그 실제 작성자다. 이름으로 추정한 제3자 언급은 확정 멘션에 섞지 않고 `candidates`의 reference/address/uncertain과 근거 종류로 전달한다. 호칭 점수는 보정된 통계적 정확도가 아니다.

**이 결과는 신원 인증/행동 권한이 아니다.** 기억·친밀도·예약은 계속 실제 `event.author` 및 기존 동의/범위 검증을 사용한다. 추정 청자·별명으로 타인의 기억을 조회하거나 관계를 갱신하거나 알림 대상을 바꾸지 않는다. 생성 모델에도 같은 경계를 전달한다.

## 별명 사전과 관리

기존 비공개 관계 SQLite에 `member_aliases`, `alias_evidence`를 추가했다. 스키마 1/2/3→4를 원자적으로 이행하며 기존 기억/관계/예약을 유지한다. 새 버전 저장소를 예전 코드로 열면 보호 검사에 걸릴 수 있으므로 다운그레이드 시 가중치와 DB를 구분한다. 운영 DB는 앱을 실행할 때 이행하며, 이번 검증에서는 격리된 QA DB만 사용했다.

- 별명은 서버와 출처 채널/스레드에 묶인다. 부모 채널의 허용 설정을 상속하는 스레드라도 별명 자료를 자동 공유하지 않는다.
- 실제 멘션/답장에 연결된 호격 또는 본인의 명시적 자기 별명 요청만 근거로 누적한다. 해당 사람의 자동 저장 동의가 필요하며 소유자의 개인 적응 허용은 기존 정책을 따른다. 단순 이름 유사성·모델 추측은 영구 근거로 저장하지 않는다.
- 메시지 ID로 중복을 제거하고 관측 수/서로 다른 작성자 수로 후보 점수를 높인다. 점수 상한은 0.89이며 반복 횟수로 자동 확정하지 않는다. 기존 닉네임에서 얻은 근거가 학습 후보 때문에 약해지지 않게 한다.
- 소유자는 앱 **사람과 관계 → 서버 → 사람 → 호칭 추가·관리**에서 채널 ID, 호칭, 확정/후보/삭제를 지정한다. 오른쪽 목록에는 상태·출처 채널·근거 수·작성자 수·점수를 표시한다. 호칭 변경은 이전 것을 삭제하고 새로 추가한다. 서버의 봇 별명 설정과 별도다.
- 모든 변경은 기존 로컬 소유자 인증을 거친다. 허용 설정에 없는 채널은 거절한다. 소유자가 같은 호칭을 두 사람에게 확정해도 임의로 한 명을 고르지 않는다.
- 원문은 저장하지 않고 별명과 최소 ID/근거 종류/시간만 저장한다. 원본 메시지 편집·삭제, 본인 기록 삭제, 탈퇴 확인, 서버/채널 삭제 시 관련 근거를 정리한다. 삭제한 원본의 근거가 뒤늦게 다시 저장되지 않도록 tombstone을 확인한다.

## 캐시·지연·알려진 한계

RAM 관측은 전체 최대 1,000개, 유휴 TTL 24시간이다. 별명 조회 캐시는 최대 128범위/60초, DB 별명은 전체 최대 3,000개, 후보당 근거는 최대 30개다. 미확정 후보/삭제 상태 및 근거는 90일 정리 대상이고 확인 별명은 명시적 삭제 전 유지한다. 소유자 변경은 조회 캐시를 즉시 비운다.

Members Intent를 켜거나 전체 구성원 목록을 요청하지 않는다. 재시작 뒤 아직 관측하지 못한 사람의 **확정 별명이 실제로 등장한 경우에만** 필요한 ID 최대 4개를 제한 조회한다. 1명당 2초 제한, 실패 후 60초 재조회 억제를 적용한다. 해당 채널 접근을 확인할 수 없으면 이름을 제공하지 않는다. 비공개 스레드의 미확인 구성원은 보류한다. 오타/미확정 후보 때문에 회원을 조회하지 않는다. 일반 메시지는 GPU 호칭 분류나 추가 회원 API 호출을 필요로 하지 않는다.

닉네임은 수신 메시지의 최신 Member 메타데이터와 제공되는 변경 이벤트로 갱신한다. Members Intent가 없는 환경에서 모든 탈퇴/닉네임/사용자별 권한 변경 이벤트의 즉시 수신을 보장하지 않는다. 관측 갱신·TTL·범위/역할 변경 시 캐시 무효화·승인 별명의 제한 조회를 보조 수단으로 사용한다. 희귀한 성씨/애칭, 짧은 오타, 아직 증거 없는 별명은 누락될 수 있다. 정확한 거절/합류 품질을 실제 사람 평가로 확정한 것은 아니다.
