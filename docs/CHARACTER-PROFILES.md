# 모델과 독립적인 캐릭터

character_profiles.py version1이 이름·소개·호칭 표시, 반말/존댓말, 에너지·차분함·솔직함·농담·감탄·이모지·설명/잡담 길이, 기존 다정함/귀여움/장난기/성별/기분/활동을 저장한다. 기분은 기존7개와 UI/검증기가 일치한다. 반복 자모 제한과 설명 완결성은 공통 정책이다. 표시 자료(소개/호칭)는 강제 행동 지시가 아니다.

숫자는 compiler가 구체 행동 문구로 바꾼다. 이름/소개는 명령이 아닌 JSON 자료이며 임의 사용자 시스템 지침을 연결하지 않는다. 고정 안전·개인정보·Discord 권한·코드 출력 제한이 우선한다. 친밀도는 권한이 아니고 성별은 고정관념을 강제하지 않는다. 성인 유머는 별도 adult_humor 설정, 기본OFF이며 기존 채널/불편·미성년 경계를 따른다. 가져오기만으로 켤 수 없다.

프로필은 로컬 characters.json 서명 envelope, 소유자 인증·32개 제한·형식 검증·원자 저장을 사용한다. 편집은 복제 저장하며 표시 이름을 바꿀 수 있다. 목록에서 적용/삭제/기본값 복원을 선택한다. 삭제는 현재 적용 사본을 지우지 않는다. 내보내기는 프로필만 plain JSON이며 토큰/기억/대화는 포함하지 않는다. 운영 설정 파일로의 내보내기는 막는다. 가져오기16KiB 제한 실패 시 기존 프로필을 지우지 않는다.

기존 슬라이더와 프로필 공통 속성은 적용 시 한 서명 transaction으로 맞춘다. 모델 선택은 프로필을 변경하지 않는다. 기존 서버별 봇 이름이 우선하고 서버별 이름이 없으면 프로필 이름을 호출 후보로 쓴다. 기존 개인 설정은 자동 초기화하지 않는다.

미리보기는 일반 입력/출력 검사·동일 GPU 큐를 쓰고 Runtime 이벤트에 넣지 않는다. 관계/기억/요약/알림 DB를 갱신하지 않는다. 결과는 RAM과 스크롤 창에만 표시한다. 단독 미리보기 중 새 모델/봇 시작을 보류해 이중 로딩을 막고 앱 종료는 작업을 취소·정리한다.

저장·적용·독립성은 단위/Controller/Tk로 검사했다. 실제 네 캐릭터×세 질문 생성 비교는 준비했으나 새 로더의 Windows 자원 부족으로 **미실행**이다. 실제 말투 차이를 검증했다고 주장하지 않는다. [검증](DISTRIBUTION-QA.md).
