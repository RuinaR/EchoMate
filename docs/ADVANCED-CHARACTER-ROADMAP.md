## 원천 혼합 규칙

사용자 추가 지시로 **라이선스 미표기 자료도 로컬 혼합 연구에 포함**한다. 원천별 라이선스 라벨/해시/버전은 그대로 보존한다. UNKNOWN을 MIT/자유이용으로 바꾸지 않으며, 원문/adapter/개인정보를 Public 저장소에 올리지 않는다. NC·접근 제한 등 명시 조건은 별도 확인하고 우회하지 않는다. 외부 캐릭터 이름·고유 배경·보호된 대사를 운영 캐릭터나 대량 정답으로 복사하지 않는다.

혼합 색인은 source pointer와 분류 축이다. 외부 원문을 모두 SFT 정답으로 승인한 것이 아니다. 기존 Topical 분할은 보존하고 동일 source family의 분할 충돌을 거절한다. Beyond의 공통 system 메시지는 실제 사건·인물 가족을 식별하지 못하므로 이번 raw 묶음은 보수적으로 한 가족에 유지했다. 그 분할을 억지로 바꿔 학습 수를 채우지 않는다. 공유 감정/관계 분류 축은 정의 참고로만 쓰고, 외부 benchmark 문항·정답을 새로운 독립 원천으로 세지 않는다.

## 지속 상태 통합 설계 — 아직 미구현/미검증

- 사실의 권위는 기존 CompanionStore·ReadReceipt·Receipt·권한/동의 epoch다. 모델이 생성한 과거·취향·약속을 저장 성공이나 새 기억으로 승격하지 않는다.
- 실제 사용자 사실, 대화 사건, 관계 변화 근거, 가상 배경, 현재 목표, 미확인 주장을 구분한다. 현재 대화 상태는 기본 RAM 범위이며 장기화는 기존 서버별·본인별 동의 안에서만 한다.
- 사건에는 출처/대상/시각/유효 상태를 연결한다. 정정/삭제/철회 뒤 검색·요약·대기 생성·송신 fresh까지 기존 검증 경로를 유지한다. 새 DB migration은 운영 파일이 아닌 임시 사본부터 검증한다.
- 기분은 지속 인격을 덮지 않는 일시 표현 상태다. 친밀함은 기억 접근권한이 아니며, 사과/불편/농담을 모델이 잘못 해석했다고 자동 친밀도·동의를 변경하지 않는다.
- 학습 adapter는 표현과 판단의 후보일 뿐 메모리/도구/참여 권한을 갖지 않는다. 현장 Runtime→SDK mock 통합은 독립적인 검증이며 standalone 생성·학습과 구분한다.

3. 새 source family 단위의 training/development/독립 평가를 고정하고 현재32 초안의 한계·중복·표현을 점검한다. 공통 규범만 다른 말투로 말하는 pair를 줄이고, 사실은 양쪽 모두 맞지만 가치 우선순위가 다른 choice/span·카드 교환 대조를 먼저 검토한다.
4. 충분히 다른 고품질 자료가 준비됐을 때만 같은 검증 설정의 작은 SFT/선호 pilot을 시행한다. 같은64의 LR/epoch 반복으로 대체하지 않는다.
5. 개발 공동 개선 신호가 있을 때만 독립·장기/Runtime 평가를 확대한다. 기존 미사용316·장부는 보존한다.

모든 GPU 실행 직전에 aggregate RAM/commit/VRAM/온도를 확인하고 2GiB GPU·RAM3GiB·commit2GiB 및 기존 온도 guard를 지킨다. 단일 상주 모델, 명시 유한 실험, 안전 경계 중단·체크포인트 보존을 유지한다. 다른 앱/게임의 창·화면·입력·프로세스 내부/파일/패킷은 조사하지 않는다. 무한 background 실행은 예약하지 않는다.
